## 1. 目的と今回の合意

iPad横画面で、左の大きな地図と右の都市雨温図を見比べ、そのまま地図の直下で気候区分の特徴と作物との関係を読める構成にする。水資源・地形は、地図に書かれた名前をタップすると右欄に解説が表示される操作に揃える。

今回の「地図下に気候区分の説明を加える」は、既存の**「気候区分の概説」を区分別に充実させて常時表示する**意味である。地中海性気候などをまとめて読める概説と、タップした対象の個別解説は、それぞれ次の場所に置く。

| 内容 | iPad横画面での場所 | 更新のきっかけ |
|---|---|---|
| 地図 | 左上。画面の主役として大きく表示 | 表示タブ、パン・ズーム |
| 都市の雨温図 | 右上 | 都市名・都市点・右欄の都市選択 |
| 気候区分の概説＋作物 | **左の地図と凡例の直下。地図と同じ列幅** | 気候タブを開くと全項目を表示。地点選択で本文を差し替えない |
| 選んだ水資源・地形の解説 | 右欄の先頭 | 地図内の名前、既存の線・面・点の選択 |
| 選んだ地点の気候区分 | 右欄の雨温図エリアに続く短い説明 | 気候の色面、または色凡例の分類名の選択 |

本書は[段階復旧設計v2.2（PR #30）](https://github.com/guchio2366-dev/insight-journal/pull/30)の第2段階に対する追補である。旧設計の配置、月の選択操作、対象選択欄、自然環境の共通ポップアップに関する記述は本書で置き換える。次の「実装せよ」は本書の変更一式を対象とし、検証・main反映・本番公開・配信確認まで進める。今回の依頼で作成する成果物は設計書とする。

## 3. 画面配置

### 3.1 iPad横・PC：960 CSS px以上

左に地図と概説、右に選択結果を置く。左列を可変幅、右列を外幅340〜400px程度とし、既存の右欄350pxの図表示を基準に調整する。右欄と地図の上端を揃える。

左列は「地図 → 凡例・短い操作案内 → 気候区分の概説」の順に、自然な高さで続ける。右欄の数表を開いて背が高くなっても、概説が右欄の底まで押し下げられない構造にする。概説の横幅は左列いっぱいを使い、横一列の項目を縦に積む。ページ全幅のフッター、地図上の吹き出し、横スクロール式のカード列にはしない。

右欄は通常のページ内に置く。独立スクロールや固定高による切り落としを設けず、選択前後で列幅・地図の大きさを変えない。都市を選んだときの自動スクロール・自動ズームも行わない。

### 3.2 960 CSS px未満

「地図・凡例・操作案内 → 選択結果の欄 → 気候区分の概説」の1列にする。選択結果へ進むまでに長い概説を読み飛ばす必要がない順序とする。ここでの選択結果欄は、横画面の右欄と同じ要素を使う。

都市選択後の「○○の雨温図へ」に加え、水資源・地形にも「○○の解説へ」の短いリンクを地図直後に表示する。リンクを押したときにだけ該当見出しへ移動する。画面回転でも要素を複製せず、都市、個別対象、数表の開閉、フォーカスを維持する。

DOMの基本順序は地図、選択結果、概説とし、横画面のCSS配置で概説を左列へ置く。CSS Grid等で右欄を左の2要素にまたがらせる場合も、右欄の高さが地図直下に空白を生まないよう、地図の行を内容高に保つ。表示されないモードのパネルは読み上げ・Tab移動の対象から外す。

## 4. 地図下の「気候区分の概説」

### 4.1 表示仕様

見出しは「気候区分の概説」。気候タブを開いた時点で、以下の全項目を表示する。未選択でも読め、都市や気候面を選び直しても並び・本文・開閉状態が変わらない構成にする。項目ごとの展開操作は追加しない。

各項目は、分類名と対応コード、気候の特徴、代表的な作物、気候との関係・必要条件の順で統一する。本文は概ね100〜160字を目安とし、必要な条件を削って短縮しない。出典は各項目に短いリンクを付ける。地図の色と結び付ける小さな色票には現行凡例の色を使い、文字の分類名・コードも併記する。

以下の8グループは読むための整理である。現行凡例に登録された23コードと、地図色・地点判定の分類は維持する。複数コードを一つの気候へ再分類しない。とくに冷涼なCsc・Cfc・Dfcまで、暖地の作物例を一律に当てはめない。

### 4.2 掲載原稿案

下表の気候の特徴は現行分類と[Beck et al.の分類資料](https://www.nature.com/articles/s41597-023-02549-6)に基づく。作物との対応は、各行の農業資料にある地域・気候・栽培条件を教育用に整理したものとする。地域紹介の資料を、その地域全体が一つの気候コードである証拠には使わない。

| 見出し／対応コード | 気候の特徴 | 作物と条件の原稿 |
|---|---|---|
| 地中海性気候／Csa・Csb・Csc | 夏に乾燥し、冬に雨が多くなる。夏の暖かさは細分類で異なる。 | **ブドウ・オリーブ。** カリフォルニアではこうした果樹が栽培される。オリーブは日照と乾燥に適応するが、実の生産には水も必要。寒冷なCscまで同じ適性とは考えず、品種・気温・水源を確認する。[UC ANR](https://ucanr.edu/blog/uc-master-gardeners-diggin-it-slo/article/olive-trees)、[USDA](https://www.climatehubs.usda.gov/hubs/california/topic/future-winegrapes-california) |
| ステップ気候／BSh・BSk | 降水が少ない半乾燥の気候。気温の高い型と低い型がある。 | **小麦。** 乾燥する大平原には、土の水分を蓄える休閑や栽培方法と組み合わせた小麦生産がある。雨だけで育てる農業と、灌漑を使う農業の条件を分けて読む。[USDA・北部大平原](https://www.climatehubs.usda.gov/hubs/northern-plains/topic/focus-croplands-northern-plains) |
| 砂漠気候／BWh・BWk | 降水が著しく少ない。高温の砂漠だけでなく、寒い冬のある砂漠も含む。 | **灌漑下のレタスなど。** アリゾナの低地砂漠では、コロラド川や井戸の水を使ってレタスを育てる。栽培を支えるのは水の供給と温度管理であり、少雨そのものがレタスに適するわけではない。[アリゾナ大学](https://acis.cals.arizona.edu/agricultural-ipm/vegetables/lettuce/irrigation) |
| 温暖湿潤気候／Cfa | 夏が暑く、明瞭な乾季がない。生育期の気温と降水を一緒に見る。 | **綿花・落花生・大豆。** 米国南東部で栽培される代表例。暖かい生育期を利用するが、雨の偏りや過湿にも対応が必要で、土壌・排水・灌漑が栽培条件に関わる。[USDA・南東部](https://www.climatehubs.usda.gov/hubs/southeast/topic/focus-croplands-southeast) |
| 西岸海洋性気候／Cfb・Cfc | 夏はCfaほど暑くなく、明瞭な乾季がない。Cfcでは暖かい期間が短い。 | **牧草・ベリー類など。** 太平洋岸北西部の海洋の影響を受ける地域では、牧草やベリー類が栽培される。比較的穏やかな気温に加え、降水・土壌条件との組み合わせが大切。冷涼なCfcへ同じ作物例を一律に広げない。[USDA・北西部](https://www.climatehubs.usda.gov/hubs/northwest/topic/agriculture-northwest) |
| 冷帯（亜寒帯）気候／Dsa・Dsb・Dsc・Dwa・Dwb・Dfa・Dfb・Dfc | 冬の寒さが強い。夏の暖かさ、乾季の時期、生育できる期間は細分類で異なる。 | **トウモロコシ・大豆・小麦など。** 中西部や北部大平原では、暖かい生育期を利用する。短い夏や霜の制約がある地域も含むため、これらを冷帯全域の適作とはしない。[USDA・中西部](https://www.climatehubs.usda.gov/hubs/midwest/topic/agriculture-midwest)、[北部大平原](https://www.climatehubs.usda.gov/hubs/northern-plains/topic/focus-croplands-northern-plains) |
| 熱帯の気候／Af・Am・Aw | 一年を通して高温。Af・Am・Awでは降水量と乾季の現れ方が異なる。 | **マンゴーなどの熱帯果樹。** 南フロリダの暖地に栽培例がある。低温や霜を避けられることが大切で、マンゴーでは開花期の雨の少なさも結実に関わる。[フロリダ大学IFAS](https://ask.ifas.ufl.edu/publication/MG216) |
| 寒帯の気候／ET・EF | ETは夏も冷涼で、EFはさらに低温になる。米国本土では高山部を読むときにも重要。 | **一般的な露地農耕には厳しい条件。** ここでは作物名を無理に割り当てず、夏の低温と短い生育期間が農業を制約することを説明する。[分類資料](https://www.nature.com/articles/s41597-023-02549-6) |

欄の末尾には「作物の育ち方は、気候に加えて土壌・水源・品種・栽培方法にも左右されます。」の1文と、既存の「同じ場所を農業で見る」リンクを置く。ここで示す作物は代表例であり、新しい作付分布データや収量予測として扱わない。

地図は1991–2020年の気候区分、雨温図は同期間のNOAA観測所平年値を継続する。「その年」の実測値や年ごとの気候区分へ切り替える仕様は追加しない。都市の位置で取得される分類を一般知識で書き換えず、既存の分類欠測も補完しない。

### 5.2 名前の見やすさと操作

名前はHTMLのボタンとして扱い、点・引出線と対応させる。タップ、クリック、Tab→Enter／Spaceで同じ説明を表示する。名前を押した操作が背景地図へ伝わって別の対象を選ばないようにし、パン終了をタップと誤認しない。

画面内の対象名は衝突を理由に間引かない。とくに五大湖周辺、ミシシッピ川と帯水層、カリフォルニアの河川・貯水池・帯水層を重点箇所として、位置をずらし引出線で区別する。長い帯水層名は折り返せるようにする。

文字は12 CSS px以上、タップ領域は44pxを目標とし、密集時も24px未満にしない。領域同士の重なりで奥の対象を選べない状態を許容しない。小さい画面で全対象を配置できない場合は、まず長名の折り返しとラベル配置領域・地図枠の高さを調整する。既存の衝突処理の最終手段で同じ位置へ重ねて済ませない。対象選択リストの復活や対象削除で解決しない。

パンで元の地点が画面外へ出たラベルは隠す。選択結果の欄は表示を保ち、選択した名前を強調する。右欄へ地図を横断する引出線は追加しない。

### 5.3 WebGLが使えない場合

都市・地形と同じく、代替地図にも操作可能な名前を載せ、同じ右欄へ表示する。水資源の現行代替画像には川・帯水層・「五大湖」の文字が焼き込まれているため、既存データから操作ラベルと重複する文字を除いた `water-interactive.webp` を作る。

`scripts/render-nature-fallbacks.py` に水資源だけの派生出力を追加し、元の投影、河川、湖、帯水層、貯水池、海流を維持する。DEMや原資料の再取得は不要。従来の `water-fallback.webp` はJavaScript無効時・全体図用に残す。新しい画像の容量とハッシュは既存のmanifestに記録する。

操作ラベルの位置は実際に画像が収まる範囲と同じ投影から求める。余白や画面回転で名前と地物がずれないことを確認する。JavaScript無効時は従来の静的代替図と読める本文を提供し、操作可能であるかのような案内を出さない。

右欄の自然環境用解説は最大1件とし、都市の雨温図と独立して管理する。概説の本文は選択状態を持たない。

| 同じ都市を再選択 | 同じ図を維持 |
| 気候の色面・分類名を選ぶ | 右欄の雨温図エリアに続けて、気候帯・分類名・コード・短い特徴・期間を表示。都市の図は保持 |
| 水資源・地形の名前を選ぶ | 右欄の個別解説を入れ替える。地図を覆うカードは開かない |
| 「解説を閉じる」 | 個別対象だけを解除し、そのモードの短い案内へ戻す。都市の選択は保持 |
| 「都市の選択を解除」 | 都市だけを解除し、雨温図の未選択案内へ戻す。独立した個別解説は保持 |
| Escape | 操作中の自然環境に個別解説があれば先に閉じる。それがなく気候の地図・図欄を操作中なら都市を解除する。他分野から非表示の都市を解除しない |
| 自然環境のタブ・他分野へ切り替える | 都市の記憶と既存URLの選択状態を維持。現在の表示に対応しない個別解説を隠す。既存の単一 `natureFeature` 状態を使い、モード別の新しい履歴は追加しない |
| パン・ズーム・画面回転 | 選択対象と雨温図を維持。位置変更だけで履歴を追加しない |
| 戻る／進む・共有URL | 既存 `city`・`natureFeature`・表示タブ・地図位置を復元。新しいパネル位置用クエリは追加しない |

個別解説の閉じる操作では元の名前へフォーカスを戻す。元が非表示なら現在の自然環境タブへ戻す。都市の解除は既存どおり、戻れる都市名、または右欄の都市選択へ戻す。選択時に右欄へ自動でフォーカスを移さず、短い `aria-live` 通知と、狭い画面の明示的な移動リンクを使う。

ラベルには、都市なら `city-climate-chart`、その他なら自然環境専用解説領域のIDを `aria-controls` として関連付ける。非表示の共通カードを指す参照を残さない。海域・欠測等の選択には分類を創作せず、該当する個別解説だけを閉じる。

自然環境専用のパネルへ接続する際も、農業・畜産・産業の共通選択カードとその位置計算は既存の動作を維持する。MapLibreは既存1インスタンス、分類判定は既存格子、雨温図は既存SVGを使う。概説の表示や都市選択に、新しい通信や図表ライブラリを追加しない。

ラベルDOMは都市12＋水資源19＋地形9の固定した集合を再利用し、パンごとに増殖させない。概説は1個、都市選択は1個、表示される都市雨温図は1個、個別解説も1個とする。12都市の元データを消去する変更とはしない。

集約表を参照する既存のページ内リンクがあれば更新する。外部から使われる旧 `climate-table-*` フラグメントについては、既知の都市IDを都市パネルに引き継ぐ小さな互換処理を設け、集約表自体は復活させない。不明な値は通常の未選択状態で扱う。

## 8. 受入条件

### 配置・情報

- 1180×820・1280×800・1024×768 CSS pxで、左上に地図、右上に都市雨温図がある。気候概説は左の地図と凡例の直下から始まる。
- 選択都市の数表を展開しても、地図と概説の間に右欄の高さ由来の大きな空白ができない。
- 820×1180・390×844では「地図→選択結果→概説」の順で横はみ出しがない。画面回転でも選択対象が変わらない。
- 気候概説の8項目が未選択時から読め、地中海性気候にブドウ・オリーブと条件がある。砂漠の作物には灌漑条件があり、寒冷な細分類へ暖地の作物を一律に割り当てない。
- 右欄冒頭の「米国本土の自然環境」、月セレクター、12都市集約表、サブナビの「対象を選択」が画面・Tab順から消えている。
- 雨温図の12か月、共通軸（降水量0〜350mm、気温−10〜40℃）、期間・出典・観測所を確認できる。図の目盛りと単位は実表示で12 CSS px以上を確保する。

### 操作・状態

- 都市12件、水資源19件、地形9件は、画面内の名前から選べる。各モードの全国表示で、衝突により名前や操作対象が消えない。
- コロラド川とミード湖、ミシシッピ川と帯水層、五大湖各湖をそれぞれ選べる。長い帯水層名の操作領域も重ならない。
- 水資源・地形の解説が右欄に表示され、地図内の共通カードと二重表示されない。名前のタップが背景へ伝播しない。
- 気候面の選択で右欄に分類が表示され、都市の図と地図下の常設概説を保持する。凡例からのキーボード選択でも同じ分類を読める。
- 選択、解除、Escape、フォーカス復帰、タブ移動、画面外の都市、URL直開き、戻る／進むが第6節どおり動く。
- WebGL無効の代替地図でも名前から同じ解説を開ける。水資源の名前に画像文字との二重表示がない。
- 農業・畜産・産業の選択カード、地図位置、分野切替後の都市記憶が維持される。

### 検証と記録

既存の `npm run check` とリポジトリの必須CIを通す。追加する自動確認は、常設概説と個別解説の独立、撤去UIに依存しない選択・復元、水資源ラベルの到達性・固定DOM、既存分野のカードへの影響を重点とする。文言と実装をそのまま写すだけのテストを増やさない。

上記5サイズで実画面を確認し、地図／右欄／概説の位置、ラベルの重なり、実描画の文字サイズを記録する。通常地図とWebGL無効時の確認結果を区別する。既存の第2段階報告は代替図での画面確認であり、新版の確認結果として流用しない。Safari・iPad実機を検証できなかった場合は、その範囲を明記する。

## 9. 実装の進め方と完了の定義

1. その時点の最新mainと他の作業差分を確認し、独立ブランチで開始する。本書の確認済みSHAへ作業ツリーを巻き戻さない。
2. 地図・右欄・常設概説の構造、原稿、不要UIの撤去を実装し、最初のまとまりをGitHubへ保存する。
3. 自然環境の個別解説を右欄へ接続し、水資源の19ラベルと代替図、フォーカス・URLを整える。
4. 第8節に絞って検証し、必要な修正と結果をGitHubへ保存する。複数の作業コミットに分けても、本書の変更一式を1つの実装範囲として完了させる。
5. 必須CI成功と最新mainへの整合を確認してPRを反映し、既存のGitHub Pagesで公開する。配信先の実際の版と操作を確認する。
6. 利用者へ公開URL、今回の変更点、確認できた画面・残る制約を提示する。

完了は、コードを保存した時点ではなく、利用者が公開URLで新しい配置と名前操作を触って確かめられる状態とする。追加確認が必要になる事情が発生しない限り、「実装せよ」の後に通常の公開の許可を取り直さない。
