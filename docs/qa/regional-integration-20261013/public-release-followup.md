## 再現と原因

既存の公開PC検査run38452131515は14地域初期・10都市選択／reload／backと43素材hashを確認後、東アジア農業の地点位置検査で失敗。自然に500ms以上安定させた診断run38453282426でも、地図枠767→781 px、camera完全同一、家畜15点のYがすべて7 px移動。run38454014576ではスクロールを0に戻しても枠高さ781 pxが残り、同じ表示位置の枠一致で失敗した。1px条件を緩めていない。

下端の品目凡例をクリックすると文書がスクロールする。高さ計算がviewport上のframe.topを読み、ResizeObserverがその時点の位置を採用するため、document上の地図位置が同じでもavailable-heightが増えて残留する。scrollイベントは説明欄だけを調整し、地図高さを戻さない。

東アジアの農業だけ、frame.top＋scrollYの文書上の位置で高さを計算する。自然・社会・産業、他地域の高さ算式は保持。品目・分布・数量・ラベル配置規則・camera・初期選択・新機能・workflow・permissions・公開先は変更しない。

実controller単体の回帰は旧コードで781px≠767pxの同じ失敗、新コードで成功。スクロール解除後の高さ／camera保持と実viewport変更時の高さ再計算も検証。実PCはクリック直後と同じ表示位置への復帰後をそれぞれ自然安定させ、camera／URL・枠と1px以内の地点位置を検証し、前後2画像も保存する。
