# アジア農業：米の分布データ v1

参照日：2026-09-25。東アジア、東南アジア、南・中央アジアの初期比較用に、同じ年・同じ定義の米の分布を提供する。農林業全体の完成を意味しない。

## 表示内容

- 作物：米（`rice`）。方式：灌漑と天水の合計（`all`）。変数：収穫面積（`harvested_area`）。
- 基準年：2020。版：IFPRI MapSPAM 2020 v2r2。2026年の作付け実況ではない。
- 元格子：WGS84、緯度経度各5分、2,160行×4,320列。南北約9kmで、東西幅は緯度によって変わる。
- 単位：**ha/元格子**。土地面積に対する割合や面積当たりの密度、収量ではない。
- 同じ田を年2回収穫すれば収穫面積は2回数える。格子の土地面積を超える値を異常と扱わない。
- 国・地方統計などを空間配分した**推計**であり、実測した農地境界、現在の作付け、地域別の正確な統計を表すものではない。

## 一次情報・利用条件

1. IFPRIの公式配布案内：[MapSPAM Data Center](https://www.mapspam.info/data/)。v2.2の案内と最新の版名を確認。
2. 今回の取得元：[CGIAR Climate Action Data HubのMapSPAM 2020](https://cgiar-climate-data-hub.github.io/catalog/spam2020/)。提供者・版・Zarr URL・CC-BY-SA-4.0の表示を確認。
3. 配布元の機械可読メタデータ：[spam2020.json](https://cgiar-climate-data-hub.github.io/catalog/spam2020.json)。処理来歴とデータ固有の利用条件を参照。
4. データ識別子：[doi:10.7910/DVN/SWPENT](https://doi.org/10.7910/DVN/SWPENT)。Harvard本体への直接アクセスは実行環境で403となったため、原配布ファイルの取得元としては使っていない。
5. [FAOの農業センサス定義](https://www.fao.org/4/a0135e/A0135E07.htm)：収穫面積と複数回の作付け。
6. [IRRIの稲作と水の解説](https://ricetoday.irri.org/how-much-water-does-rice-use/)：降水・灌漑、水の損失と再利用。

今回の派生JSON・PNGは、取得したCGIAR配布物の表示に合わせて **CC BY-SA 4.0** とする。出典・加工内容を `LICENSE.txt`、画面の出典欄に記す。データ提供元の推薦や保証を示唆しない。MapSPAMサイトの古い一般規約と原Dataverseの規約をこの配布物の利用条件に置き換えて断定しない。

## 加工と固定入力

生成スクリプト：`scripts/atlas-asia-agriculture.py`。Pythonの無償OSS（NumPy、Pillow、numcodecs 0.16.5、Shapely 2.1.2）だけを使用する。既定では元データをリポジトリの隣の `asia-agriculture-cache` に保存し、公開成果物に巨大な元ファイルを混ぜない。

```text
python scripts/atlas-asia-agriculture.py
# 独立した依存ディレクトリを使う場合
python scripts/atlas-asia-agriculture.py --dependencies <directory>
```

- Zarrメタデータと `harvested_area/c/0/1/0/0` のMD5を固定し、取得物が変われば停止する。各入力のSHA-256も `provenance.json` に残す。
- 実際の座標配列を復号し、作物index 1がrice、方式index 0がallであることを検証する。
- 元のZarr v3シャードのCRC32C付き索引を検証し、Bloscで各90×90格子を復号する。
- 既存 `regional-countries.json` の国境に格子の中心が入る場合だけ、対応する地域へ表示する。イラン・ロシアは今回の対象に含めない。
- 境界や海岸の形状を5分格子へ移すため、海岸・小島・国境沿いの格子が落ちる場合がある。**このマスク後の格子から正確な国別総計を公表しない。** 国境表示は既存地図の方針を継承する。
- 照会値は元格子のhaを小数第2位へ丸め、隣接格子の値を混ぜない。
- PNGはWeb Mercatorへ最近傍で投影する。MapLibreのimage sourceに未投影の緯度経度画像を貼ると南北にずれるため、照会の経緯度格子と表示用投影を分ける。

## 凡例・欠測

| 収穫面積/格子 | 色 |
| --- | --- |
| 1–10ha未満 | `#d9f0a3` |
| 10–100ha未満 | `#addd8e` |
| 100–1,000ha未満 | `#78c679` |
| 1,000–5,000ha未満 | `#31a354` |
| 5,000ha以上 | `#006837` |

1ha未満は地図上で着色しない。0、1ha未満、欠測、対象外はすべて透明になるため、凡例横にその旨を必ず表示する。照会では有効な0と欠測を分ける。元データに値がない場所を0へ補完しない。

モンゴル・シンガポールは今回の米変数に有効な格子がない。モルディブは既存の島の形状内に5分格子の中心がなく、この粒度では表示できない。これらを「米が生産されない」という統計的結論にしない。

## UI接続契約

各地域の `{regionId}.json` に `bounds`（西・南・東・北）、`format: image`、`imageUrl`、`queryUrl`、`coordinates`（左上→右上→右下→左下）、`year`、`units`、`breaks`、`colors`、`source`、`method` を保持。

照会JSONは次の形式：

```text
{bounds, width, height, cellSize, positiveCells: [[index, ha], ...], validRuns: [[startIndex, count], ...]}
```

行は北→南、列は西→東。`index = row * width + column`。有効範囲にありpositiveCellsにないものは丸め後の0、validRunsの外側は欠測または対象外。照会関数 `readAsiaRiceCell` を `src/data/atlas/asia-agriculture.ts` に用意。アセットURLには既存サイトのbaseパスを付加する。

画面の色だけで国別の0と欠測を判断させない。国を選択した際はmanifestのcountriesを参照してデータ有無を説明する。グリッド選択は農地そのもののクリックではなく、「この約9km格子の推計」を示す。

## 確認結果

- 元シャード821,001 bytes。復号後の世界の米収穫面積合計は162,924,228.88ha（内部の復号確認値。画面の国別統計には使用しない）。
- 3地域のPNG合計約145KB。地域別照会JSONは約0.58–0.78MBで、選んだ地域・農業タブに入った時だけ読み込む。
- 東アジア：有効52,221格子、着色39,907格子。
- 東南アジア：有効42,019格子、着色34,458格子。
- 南・中央アジア：有効63,984格子、着色40,570格子。
- 照会の丸め誤差は0.011ha以下であること、有効格子数とrun長合計が一致することを生成時に検証。
- 既知の位置（長江下流、新潟、黒竜江、メコンデルタ、チャオプラヤ川下流、バングラデシュ、パンジャブ、シルダリア川付近）に米の有効格子があることを確認。
- 実データ766点でTS照会の格子index・haが一致。3地域で推計0、欠測、範囲外、NaNを別々に確認。
- 生成を繰り返し、公開成果物12ファイルのハッシュが一致。3地域のPNGを視認して方位・分布の大きなずれがないことを確認。画面への重ね合わせとモバイル操作はUI統合時の確認範囲。
