## 0. 次の担当が最初に読むこと

目的は、農業全体の販売収入を「作物と畜産の割合 → それぞれの品目構成」で理解し、同じ地図上で作物と畜産の立地を見比べられるようにすることである。

- 大分類のタブは「農業」のまま。その内部に作物・畜産を置く。
- 全米統計は全体の100%積み上げ横棒、その下に作物内・畜産内の横棒一覧を常時表示する。グラフの母数を明示する。
- 地図には「作物」「畜産」のチェックボックスを置く。初期値は両方オン。すべての作物、すべての対象畜種をそれぞれ一括で表示する。
- 作物は現在の色面。畜産は主要集積地域の記号と短い名称。畜産地域を選んだときだけ、根拠のある概略範囲を輪郭で示す。
- 地図の表示操作は、カメラ、右欄の全米統計、下部の既存作物統計を不用意に変えない。
- 地図の対象は米国本土48州。全米販売収入はUS系列の対象範囲を維持する。カナダ・メキシコ等の未収録域を生産ゼロと扱わない。
- 現行のAstro、MapLibre、自己配信データ、GitHub Pagesを再利用する。有料API、常駐サーバー、新しい実行時グラフライブラリは不要。

判断の優先順位は、最新のユーザー指示 → 本書 → 本書と矛盾しないv4.0・現行データ仕様である。本書のv5.0は設計書の版であり、既存の地理資産ディレクトリ `v3/` を一括変更する指示ではない。

実装を開始する際は本書の12章を使う。設計書を読むだけで再調査・再設計を全面的にやり直す必要はない。畜産の地域データは未取得なので、6章の検証を先に行う。

## 3. 販売収入の定義・分類・計算

### 3.1 母数

出典は[USDA ERS Farm Income and Wealth Statistics](https://www.ers.usda.gov/data-products/farm-income-and-wealth-statistics)。2026-09-03公表の2025年推計を使う。今回、前回取得済みの原CSVを再読し、入力ハッシュの一致も確認した。

| 区分 | 原データの値：千ドル | 10億ドル換算 | 全体比 |
|---|---:|---:|---:|
| 全品目 | 541,987,513 | 541.987513 | 100% |
| 作物 | 238,356,114 | 238.356114 | 43.978% |
| 畜産物等 | 303,631,399 | 303.631399 | 56.022% |

画面は「農畜産物の販売収入」「作物 44%」「畜産 56%」、総額は「約5,420億ドル」とする。作物内の母数は238,356,114千ドル、畜産内は303,631,399千ドルである。例えば牛・子牛44.0%は畜産内の割合であり、全体比24.7%と取り違えない。

定義欄には、農産物販売による現金収入であること、利益・付加価値・生産数量とは異なることを記す。補助金、農外収入、家庭内消費、在庫評価調整は販売収入の内訳へ加えない。農場間の飼料・家畜等の取引を含む販売収入を、GDPのような重複排除済みの付加価値と説明しない。

全米統計と本土48州の地図は対象範囲が異なる。画面下の出典に「統計：全米／地図：米国本土」と短く示す。元系列の畜産物等には養殖なども含まれるため、残余の定義欄で説明する。

原値の分類合計は238,356,115千ドル、作物の公表総額は238,356,114千ドル。**千ドル単位の公表丸めに伴う差1千ドルを確認した。** 生の値を変えずに照合記録へ残す。比率の分母は公表総額を使う。

分類の補足はグラフ直下の「内訳と定義」で読めるようにする。

- とうもろこしは穀粒用の系列。スイートコーンを追加して野菜と二重計上しない。
- 小麦・米などはFood grains。小麦9,963,448、米2,913,536千ドルを数値表で示せる。親分類にこれらを再加算しない。
- 牧草等はFeed cropsから穀粒用とうもろこしを除いたもの。干し草だけではなく、ソルガム、大麦等を含む。「すべて牧草」と説明しない。
- 綿花は綿繊維と綿実を含む系列。作物別世界生産・輸出統計の綿繊維基準と同一ではない。
- 砂糖原料はサトウキビとテンサイ。精製糖の売上ではない。
- 落花生・菜種等は大豆以外の油糧作物、小規模な別途公表作物、たばこ等をまとめた表示分類。元統計のMiscellaneous cropsとは別である。
- その他11.3%は原統計の一括分類そのもの。これを根拠なく「苗木」等へ言い換えたり、別年の園芸センサスで無理に割り振ったりしない。短い補足は「その他は元統計の一括分類」。

金額の構成を示すグラフなので、価格変動でも比率が変わる。耕地面積や収穫量の比率と同一視しない。

### 3.5 照合・更新規則

1. 全品目＝作物＋畜産物等は原単位で完全一致させる。
2. 子分類合計と親分類は差額を記録する。許容差は使用した公表丸め値の個数に基づく丸め誤差の上限以内とし、この版で確認した差は各1千ドル。桁の大きい差や欠測を「丸め誤差」と呼ばない。
3. 比率を先に丸めて計算しない。小数1桁での表示合計が99.9%等になる場合は表示の丸めとして扱い、特定の品目を改変しない。
4. 原データの欠測は0にしない。必要系列が欠けたら生成を失敗させる。
5. 畜産地図の年を揃えるために販売収入を2022年へ後退させない。地図・販売収入・既存輸出統計はそれぞれの対象年を表示する。
6. 2025年推計と2026年予測を混在させない。統計更新は同一公表版の全分類をまとめて行う。

### 4.2 統計欄

全体は作物・畜産の2色による100%横棒。割合と区分名を直接表示し、全体額を隣接させる。その下に見出し「作物内の割合」「畜産内の割合」を置き、各分類の横棒と割合を全行表示する。

内部の横棒は2群共通の0〜50%軸を初期値とし、0%を起点にする。50%を超える分類がある更新時は両群とも0〜100%へ変更する。軸の終端値を各群に明示する。群ごとに最大項目へ自動スケールして同じ長さにしない。分類間の絶対金額比較が必要なら、隣接する各群の総額・定義表を読む構成にする。

作物11行・畜産5行の計16行を基本とする。行高17〜20px、ラベル・割合11〜12pxを初期値として、実寸の読みやすさを確認する。ラベルはCSSで省略しない。長いラベルが折り返す場合は短い表示名と定義表を使う。

色は作物群を緑系、畜産群を茶系とし、親横棒と揃える。作物ごとに11色を新設する必要はない。各行に名前と割合があるので、色だけで品目を識別させない。地図の色面は現行配色を維持する。

親比率・両群の内訳・輸出入を収める目安として右欄560〜630pxを見込む。見出し・概説を短くし、原値の表と長い定義だけを展開式にする。内訳の片方を折り畳んだり、右欄だけに独立したスクロールを設けたりすることを標準解にしない。

それでも実寸で収まらない場合の代替は、子2群を100%横棒と常時見える名称・割合一覧にする省高表現。この場合も項目省略・母数変更・文字縮小で解決しない。数値一覧の読みやすさを画像で比較して決める。

### 4.3 概説の初稿

> 米国の農畜産物販売収入は約5,420億ドルで、作物が44%、畜産が56%を占めます。作物ではとうもろこし・大豆、畜産では牛・子牛が大きく、果物・野菜や家禽・卵にもまとまった規模があります。

比率の基準年を見出し近くに表示する。輸出入の差額説明は輸出入グラフ側に短く置き、冒頭を長くしない。収入構成だけで畜産の成長や生産性を断定しない。

## 5. 地図の見せ方と操作

### 5.1 同時表示

| 層 | 表現・意味 |
|---|---|
| 基礎地理 | 現行の海岸、地形陰影、河川、湖、国境、薄い州境・州名 |
| 作物 | 現行の概略栽培域。全作物を同時表示 |
| 畜産 | 小さな輪郭記号＋肉牛／酪農／養豚／肉用鶏／採卵の短い名称 |
| 選択した畜産地域 | その地域だけの概略輪郭。原則として面は塗らない |
| 選択説明 | 一つのカード。選択域、主要ラベル、操作部を避ける |

畜産の記号は牛、乳、豚、鶏、卵を連想できる単純なSVGを使い、端末で絵柄が変わる絵文字を主記号にしない。記号は同じ画面サイズで表示し、牛と鶏の記号の大きさを頭数比較に使わない。色だけに頼らず短い名前を付ける。

新しい多数の面塗り、全畜種の密度ヒートマップ、飼料の流れを示す常時矢印は追加しない。作物の色が読みにくい場合は畜産記号の白縁・位置を調整する。作物の不透明度を変える場合も両方表示と単独表示で意味・凡例が変わらないようにする。

### 5.2 重なりと記号集約

地域を示す地理座標と、文字・記号の画面上の配置を別々に保持する。記号を少しずらす際は引出線で元の地域へ対応させ、地理データ自体を移動しない。

画面で衝突する近隣記号は、同一の説明地域に属するものを優先して「養豚・採卵」のような一つのボタンにまとめる。所属地域が異なる場合は地域名も表示し、同一点・同一農場で営まれていると誤読させない。統合マークは頭数・農場数を表示するクラスターではない。

集約は低倍率の表示上の処理であり、データを削除しない。拡大すると個別記号へ戻る。主要な独立地域や畜種を、端末幅だけを理由に無表示にしない。全候補は集約ボタンまたは畜産凡例から到達できるようにする。

初期記号の候補数はデータを見て決める。全国を数個の代表都市のピンだけで済ませない。広がりが重要な地域では、根拠のある複数の集積域に分ける。

### 5.3 タップの優先順位

| 操作 | 結果 |
|---|---|
| 畜産記号をタップ | 畜産地域を選択し輪郭とカードを表示。イベントを地図下の作物へ伝播させない |
| 畜産記号と作物が重なる | カードに「この場所の作物」の小さな選択肢も出し、作物へ到達可能にする |
| 集約ボタンをタップ | 集約された地域・畜種の候補を表示。選んでカードへ進む |
| 作物域をタップ | 現行の作物説明を表示。同地点に畜産候補がある場合だけ併記 |
| 空白をタップ／閉じる | 選択と輪郭を解除。表示チェック、カメラ、全米統計は維持 |
| 作物／畜産をオフ | 該当の記号・色面・凡例だけを非表示。選択対象を含む層を消す場合はカードも閉じる |
| 両方オフ | 基礎地理を表示。「作物か畜産にチェックすると分布を表示」の短い案内 |
| 他分野へ移る | 畜産記号・農業用操作部を非表示。戻れば表示チェックを復元。カメラは維持 |
| 詳説リンク | 地図下の対応する作物／畜産解説へスクロールし、見出しへフォーカス |

選択状態は統計の絞り込みではない。畜産記号をタップして作物の輸出先グラフが畜産のグラフに見える挙動を作らない。

### 5.4 iPhone・iPad

チェックボックスはラベル全体を44px程度のタップ対象にする。狭い画面で各畜種のフィルターを常時並べない。地図の操作欄は1行を基本とし、既存の長いレイヤー注釈を短い年次表記へ整理する。

記号は見かけを小さく、タップ領域は44pxを目標にする。タップ領域が競合する場合は記号集約で対処し、透明な巨大領域で下の作物を覆わない。キーボードでもチェックと記号／候補を選べるようにする。

画面上の説明はPC2〜3文、iPhone1〜2文を目安に編集する。短縮版でも原因と結果を切断しない。カードが選択地域・重要地名に重なる場合は同じカードを地図直下へ置く。自動ズーム・自動パンは行わない。

## 6. 畜産分布のデータ準備

### 6.1 確認済みと未確認

[2022 Census of Agriculture](https://www.nass.usda.gov/Publications/AgCensus/2022/index.php)と[Ag Census Web Mapsの概要](https://www.nass.usda.gov/Publications/AgCensus/2022/Online_Resources/Ag_Census_Web_Maps/Overview/index.php)で郡単位の地理統計が提供されていることを確認した。Web Mapsは収録項目の一部であり、5畜種の全指標が同じダウンロードに揃うとはまだ確認していない。実装時はQuick Statsまたはセンサスの郡別表を併用する。

[Web Mapsのデータ説明](https://www.nass.usda.gov/Publications/AgCensus/2022/Online_Resources/Ag_Census_Web_Maps/Data_download/index.php)は、秘匿値(D)について数値欄は空でも公式の階級幅が与えられる場合を説明している。値がないこととゼロを区別するために、この情報も保存する。

今回確認したのは提供元・メタデータと取得の入口である。畜種ごとの全郡データ、正確なクエリ、秘匿率、地理資産、完成原稿は未作成。本書に架空の観測値・境界・完成済みフラグを入れない。

### 6.2 対象指標

| 表示分類 | データ準備で確認する指標 | 解釈の注意 |
|---|---|---|
| 肉牛 | 繁殖用肉用雌牛の飼養頭数。肥育は別系列の在槽頭数または肥育出荷頭数 | 全牛・子牛には乳用牛も含まれる。「全牛−乳牛」で独自推計しない。繁殖と肥育の数値は足さない |
| 酪農 | 乳用牛の飼養頭数 | 生乳の販売収入・産乳量そのものではない |
| 養豚 | 豚の飼養頭数 | 年間出荷頭数と混ぜない。繁殖・肥育の違いは根拠のある原稿で補足 |
| 肉用鶏 | ブロイラー・肉用鶏の年間販売羽数を優先 | 一時点の在庫羽数と混ぜない |
| 採卵鶏 | 採卵鶏の飼養羽数。種鶏等を含むか要照合 | 鶏卵生産量、全鶏、肉用鶏と同一ではない |

年は2022年センサスを共通基準とする案を採る。出荷・在庫など畜種に適した指標を使うため、全畜種を一つの密度尺度で比較しない。農場数を頭数と混ぜない。州別の新しい統計は傾向確認には使えるが、郡分布の対象年を新しく表示する根拠にはしない。

肉牛は画面上の分類を一つに保ち、データには繁殖・肥育の段階属性を持たせる。両者が異なる集積地を持つ場合は別の記号・解説地域にする。必要指標が揃わない場合、収録できた段階を明示して代替案を報告する。

### 6.3 地域化の規則

1. 原データを対象年・畜種・指標・単位・郡FIPS・公開状態で正規化する。同一指標の重複、州合計行、農場規模別内訳の重複を除く。
2. 2022年対応の郡境とFIPSで照合する。加工・面積・距離の計算は米国本土向け等積座標系EPSG:5070、配信用はWGS84の経度・緯度とする。
3. 内部検証用に郡別分布図を作り、公的な分布図・地域解説と比較する。頭数、密度、公式階級のどれで地域を選んだかを記録する。広い西部の郡を面積だけで過大・過小評価しない。
4. 根拠郡の集合や公式地域区分を基に、主要集積地域を編集する。採用基準・対象郡・境界作成法・省略した地域を地域ごとに保存する。データを見ずに全国一律の平滑化半径や閾値を確定しない。
5. 地図に出す輪郭は「資料に基づく概略集積地域」であり、観測した農場境界ではない。疎な郡内に任意の精密境界を作らない。遠く離れた地域を凸包で結んで一つの産地にしない。輪郭を支持できない地域は輪郭なしの地域表示とし、その理由を記録する。
6. 海・湖を除外し、地域の中または対応する場所にラベルの基準点を置く。記号の見栄えのために観測値や地理範囲を動かさない。
7. 5畜種ごとに全体図と既知の集積地・非集積地を照合する。秘匿・未収録による空白を低生産と解釈しない。

郡情報から衛星データと同じ位置精度は得られない。統計を地域化したことを短い表示と詳しい加工記録で説明する。元の郡境を隠しただけで自然条件に一致する精密分布になったと扱わない。

[NASSの2017年点分布図の方法](https://www.nass.usda.gov/Publications/AgCensus/2017/Online_Resources/Ag_Atlas_Maps/)も、点が実際の農場位置ではないことを明示している。そのPDFの点を農場座標として取り出したり、2022年の観測地点として流用したりしない。旧図は方法と地域傾向を照合する参考に限定する。

### 6.4 欠測・公開条件

- 公表された正確な値、公式階級、秘匿、未取得を別状態で保持する。
- 公式階級から中間値を作って「頭数」にしない。公式階級は公式階級として地域の根拠に使える。
- 秘匿値の逆算や非公開値の復元を行わない。全国・州合計からの差を特定郡の実数に割り当てない。
- 境界・記号には出典ID、観測年、指標、加工版、地域化の根拠を関連づける。
- 2022年の畜産、2023年の作物、2025年の販売収入を並べる理由は構造理解である。同年の厳密な空間因果分析と説明しない。

配布ファイルごとに取得URL、ライセンス／利用条件、取得日、公開日、対象範囲、単位、入力SHA-256、処理パラメータ、出力ハッシュを台帳へ保存する。USDA由来というだけで第三者の地図画像の権利を同一視しない。

## 7. 地域解説と下部コンテンツ

地図カードは地域固有の説明、下部は畜種の一般的な特徴と米国での立地を扱う。カードの原稿構造は「その場所の条件 → 畜産への作用 → その地域への定着」。気候だけに因果を限定しない。

| 原稿 | 必要な要素 |
|---|---|
| 肉牛 | 放牧・繁殖と肥育の違い、草地・飼料・水・加工施設との関係 |
| 酪農 | 飼料、水、暑熱、搾乳・集乳・加工の条件。冷涼さだけで立地を説明しない |
| 養豚 | 飼料、繁殖・肥育、処理・加工、輸送、地域の生産体制 |
| 肉用鶏 | 飼料、鶏舎の環境管理、孵化・飼料工場・処理施設の関係 |
| 採卵鶏 | 採卵と肉用の違い、飼料、集荷・加工・販路、飼養環境 |

地図上では「この場所の作物」「畜産の詳説へ」を必要に応じて添える。近くにとうもろこしがある事実だけで、地元調達の数量や輸送経路を断定しない。根拠のない飼料輸送矢印を描かない。

5種類の下部解説は、一般的特徴 → 米国の代表的地域と条件 → 定着を支える仕組みの順に200〜400字程度を初稿目安とする。実際の地域名と因果主張はデータ・公的資料・大学Extension等を照合してから執筆する。既存の「作物の一般的特徴→地域との適合」という文章方針を継承する。

通常は地図下に畜産5分類の短い見出し・概説を置き、長文を読む部分だけ展開できる。地図からのリンクは対象を展開して見出しへ移動する。畜産を地図でオフにしても、下部の畜産解説を消さない。

各原稿には通常文、狭い画面用の短文、出典、対象年、地理的適用範囲、確認状態を持たせる。「査読済み」という語は外部査読を受けていない編集原稿に使わず、「出典を確認した解説」とする。

### 8.2 データ型の契約例

```ts
type LivestockKind = 'beef' | 'dairy' | 'hogs' | 'broilers' | 'layers';
type AgricultureLayers = { crops: boolean; livestock: boolean };
type MapSelection =
  | { kind: 'crop'; cropId: string; regionId: string | null }
  | { kind: 'livestock'; kindId: LivestockKind; regionId: string }
  | null;

type ReceiptItem = {
  id: string; label: string; valueThousandUsd: number;
  sourceKeys: string[]; calculation?: string;
};

  id: 'crops' | 'livestock'; label: string;
  totalThousandUsd: number; items: ReceiptItem[];
  reconciliationThousandUsd: number;
};

type LivestockRegion = {
  id: string; kindId: LivestockKind;
  phase?: 'breeding' | 'finishing';

  geometryFeatureId?: string;

```

これは本書内の型契約であり、今回アプリへ追加したコードではない。`labelAnchor`は地域の表示基準点であって農場位置ではない。加工記録のsupporting FIPSや秘匿率等は公開軽量データと分けて保持できる。

### 8.3 URLと状態遷移

既存の位置・倍率・作物リンクを壊さず、次を追加する。

| URL項目 | 意味・正規化 |
|---|---|
| `agriLayers=crops,livestock` | 両方オン。順序をこの順へ正規化 |
| `agriLayers=crops`／`livestock`／`none` | 作物だけ／畜産だけ／両方オフ |
| `animal=<kindId>` | 選択した畜種 |
| `animalRegion=<regionId>` | 選択した畜産地域 |
| 既存 `crop`・`region` | 作物選択用として残す。畜産地域IDを混ぜない |
| 既存 `stats` | 下部の作物統計選択のまま。畜産のフィルターへ転用しない |

`agriLayers`がない旧URLは両方オンへ移行。未知・空の値は既定値へ戻し、重複トークンを除く。`none`と他トークンの混在は不正値とする。畜種と地域の対応が不正なら選択を解除する。

非表示の層への選択がURLにある場合は表示チェックを優先して選択を解除する。両方の選択が書かれた不正URLは互換性のため有効な旧作物選択を優先し、不要な畜産選択を除く。畜産を正規に選ぶ操作ではcrop・regionを消すが、statsは消さない。

操作による層変更・選択には履歴を追加し、カメラ移動は現行同様に履歴置換を使って大量の履歴を作らない。リロードと戻る／進むでチェック、選択、カメラを再現する。農業以外の分野でagriLayersを保持しても、その分野に作物や畜産を描かない。

`writeAtlasState`の位置引数が増えすぎないよう、必要なら後方互換の状態オブジェクトへ整理する。呼出元を一括確認し、単一の読み書き関数で検証する。

### 8.4 地図の共有と性能

MapLibreインスタンス・Canvas・基礎地理は一つを維持する。畜産は独立したGeoJSONソースと選択輪郭のレイヤー、上部DOM記号で追加する。表示・非表示でソースの再取得や地図の再生成をしない。ラベルはrequestAnimationFrame単位でまとめて配置する。

依存ライブラリは現行で足りる。統計はAstroでHTML/SVGを出力する。畜産地域の処理はビルド前のPython等で行い、全国の原CSV・郡図形を端末へ送らない。GitHub PagesのビルドごとにUSDAへ問い合わせない。

追加配信用データと短文の目標はgzip後250KB以内、代替図は各350KB以内、地域レコードはまず100件以内を目安とする。これは性能の予算であり、恣意的に地域を消すための上限ではない。上回る場合は段階読み込みや図形簡略化を検討し、影響を記録する。

畜産データは農業を開いたときに読み、同一訪問中はPromiseを共有する。読み込み途中にチェックを切り替えても、後から完了した古い処理が表示状態を巻き戻さない。

## 9. 失敗時・非JavaScript時の表示

| 状態 | 表示と挙動 |
|---|---|
| WebGL2利用不可 | 同じ配信地理資産から作った代替図を表示。全米統計・解説は読める |
| 畜産だけ読み込み失敗 | 作物・基礎地理・統計を維持。「畜産データを読み込めません」と再試行を表示 |
| チェック後のロード中 | チェック状態を保持して短く読込中を示す。未表示を「畜産なし」と解釈させない |
| 一部指標を提供できない | 凡例と出典に収録範囲を明示。対象5分類が揃った完成版とは報告しない |
| JavaScriptなし | 既定の両方表示の静的図、全米統計、下部解説を出力。操作チェックは隠し、静的図の各版へのリンクを提供 |

JavaScriptが動くWebGL失敗時は、作物のみ・畜産のみ・両方・基礎地理の4状態に対応する代替図を切り替える。既存の基礎地理・作物図は再利用し、新しく畜産のみ・両方の2図を作る。固定図のピクセル座標を本番GISの位置情報へ変換しない。

代替図では凡例／地域一覧から畜産を選び、説明は地図直下へ出す。画像内のクリック座標だけを唯一の入口にしない。GPU表示に固有の検証と代替図の検証を区別する。

実画面では未選択、肉牛、酪農、養豚＋作物の重なり、肉用鶏／採卵の候補、片層オフ、両方オフを確認する。スクリーンショットを取得して自分で確認し、操作部・文字・カードの衝突を直す。

ブラウザのCSS viewport、タッチエミュレーション、WebGL実描画、実機iPad/iPhone Safariは別々に報告する。クラウド環境で代替図しか出ない場合、それをライブ地図でのタップ・拡大検証と報告しない。

## 11. 未決事項と相談が必要になる条件

### 11.1 担当者が調べて決める事項

| 事項 | 解決方法 |
|---|---|
| 5分類の正確な取得クエリ・公開範囲 | 2022年データ、定義表、欠測率を照合する |
| 肉牛の繁殖・肥育を裏付ける指標 | 別系列として確認し、一方を他方の代用にしない |
| 地域数・地域化の閾値・輪郭 | データ検証図を見て決定、記録する。実装値を仮定のまま公開しない |
| 記号の集約距離・カード位置 | 端末別画面とタップ検証で調整する |
| 16行の統計と貿易の収まり | 余白と短文を調整。必要なら4.2の省高案を実寸比較する |
| 自然環境側の並行作業 | 実装開始時にmain／PR／共有ファイルを再確認して統合する |

### 11.2 ユーザーに判断を求める条件

- 公的データの不足で5分類の一つを全国として示せず、収録分類・対象地域・対象年を大きく変える必要がある場合。
- 根拠のある地域表示を保つと、iPhoneで作物・畜産を同時に読む条件を満たせず、単独表示を初期値にする等の変更が必要な場合。
- 有料サービス、追加アカウント、認証操作など既存環境を超える作業が必要になり、無料の代替では目的を満たせない場合。

現時点でこの条件に該当する問題は判明していない。畜産分布の精度は6章の範囲を前提にしており、正確な農場位置まで得られると約束していない。記号の形や余白の微調整で追加承認を求める必要はない。

## 12. 実装順序と引継ぎ

1. **現況照合**：main・開いているPR・新しいユーザー指示を確認。自然環境等の共有コードの変更を確認する。現在の `docs/atlas-qa.md` と本書を読む。
2. **販売収入データ**：原単位で親子構造を生成、分類表と照合。既存の輸出・世界生産は再計算の必要がなければ変更しない。
3. **統計欄の実寸確認**：全体＋両群内訳＋輸出入を現在の右欄に配置し、iPad横とiPhone縦で確認する。
4. **畜産の資料と地理データ**：原データ取得、定義・秘匿の検証、内部図、地域化、原稿。完成データと記号の根拠を先に作る。
5. **地図の追加実装**：チェック、記号、集約、選択輪郭、説明、URL、他分野との共存、部分読込失敗を実装する。
6. **下部解説・代替図**：5分類の説明と対応リンク、WebGL失敗／JSなしの表示を整える。
7. **受入確認**：A01〜A18、既存check、端末別スクリーンショット。未検証範囲を区別して記録する。
8. **既存公開手順**：変更をPRにまとめ、CI成功と意図した差分を確認して既存GitHub Pages手順で反映。実装・公開が指示されたターンで行う。

本書作成ターンでは新規設計ファイルだけを設計用ブランチに保存する。公開サイトへ新機能を反映したと報告しない。実装時はデータとUIを段階的なコミットにできるが、未完成の畜産ボタンや仮の領域を本番へ出さない。

実装完了報告は確認用URL、iPad横・iPhone縦の画面、使用したUSDAデータの年・指標、検証結果、実機確認の範囲、残った制約を簡潔に示す。

次のモデルに渡す指示は次で足りる。

> GitHubのguchio2366-dev/insight-journalで、codex/atlas-livestock-design-v5ブランチのdocs/atlas-agriculture-livestock-design-v5.0.mdを読んでください。既に統合済みならmainの同ファイルを使います。mainと開いているPR・共有ファイルの変更を確認してから進めてください。農業タブ内の作物／畜産の階層統計と地図の同時表示が目的です。12章の順でデータ準備、実装、端末別検証を進め、既存の公開手順で反映してください。販売収入の母数、郡統計の位置精度、作物と畜産の重なり、既存の自然環境側の変更を特に確認してください。
