## 1. 決定事項と学習目的

上位タブ「農業」を「農林業」に広げ、その中に「作物」「畜産」「林業」を置く。林業の初期項目は「森林資源と木材生産」の一つとする。独立した上位タブは増やさない。

持ち帰ってほしい問いは、**「森林が広がる場所と、木材を生産する場所はどう違い、その違いを何が生むのか」**である。森林の成立条件と、管理・伐採・輸送・加工への接続を地図とともに理解する。産業規模の大小を掲載の唯一の基準にせず、自然条件と生産活動の関係を学べることを重視する。

農畜産と同じ数の項目や統計図をそろえる必要はない。林業を、とうもろこしや肉牛と同じ分類階層の品目として直接並べない。

## 2. 対象範囲とタブの役割

既存ページと同じ米国本土の連続48州を基本範囲とする。カナダ・アラスカ・ハワイを含む全北米の値と混在させない。

| 置き場所 | 担当する内容 |
| --- | --- |
| 農林業 | 森林資源、育成・管理、伐採、木材生産の立地と用途 |
| 自然環境 | 植生・森林の成立条件、降水・気温・地形 |
| 主要産業 | 製材、紙・パルプなどの加工、工場・雇用・付加価値 |

初版では木材生産を中心に扱う。生物多様性、炭素、観光、山火事等は木材生産の理解に必要な範囲で触れ、独立した機能群へ拡大しない。漁業追加は本設計の範囲外。

## 3. 名称変更と既存概説の扱い

- ユーザー向けタブ表示を「農林業」に変更する。見出し・パンくず・アクセシブル名なども文脈に合わせて更新する。
- URL `/atlas/north-america/agriculture/` と既存の内部フィールドID `agriculture` は維持する。既存リンクを壊す名称一括置換はしない。
- 初期地図は現在の作物・畜産表示を維持し、林業の追加データは選択時に読み込む。
- 概説は「米国の農林業」とし、短い導入で作物・畜産・林業の三分類を示す。現在の販売収入・貿易図は「農畜産の概況」として対象を明示する。
- **既存の農畜産販売収入を農林業全体の合計に言い換えない。** 林業の売上、木材製品の出荷額、付加価値を農畜産の販売収入へ単純加算しない。

## 4. 選択UIと画面構成

地図下に分類名と具体的な選択肢を常時表示する。分類を先に開く操作を要求しない。

| 分類 | 常時見える選択肢 |
| --- | --- |
| 作物 | 現在の作物の選択肢 |
| 畜産 | 現在の畜産の選択肢 |
| 林業 | 森林資源と木材生産 |

### iPad横・広い画面

| 左側 | 右側 |
| --- | --- |
| 林業の地図、短い凡例、三分類の選択肢 | 「森林資源と木材生産」の見出し、冒頭要点、項目別説明、本文内の比較ボタン |
| 地図の下 | 必要な統計を内容に応じて1〜2枠 |

地図と説明の高さを既存の仕組みでそろえ、長い解説は右側の枠内で読めるようにする。図を増やして高さを埋めない。本文内ボタンは関連段落の直後に置く。

### 狭い画面

地図 → 選択肢 → 解説 → 統計の順に並べる。解説の枠内スクロールは原則使わず、ページ全体で読めるようにする。ボタンは折り返し、ラベルを省略しすぎない。

## 5. 地図の設計

林業選択時は、作物の色面・畜産記号を一時的に隠して林業表示へ切り替える。利用者が設定した作物・畜産の表示状態とカメラ位置は保存し、戻った際に復元する。選択のたびに全国表示へ強制リセットしない。

林業の地図では次の情報を区別する。

| 情報 | 表示候補 | 読み取れること |
| --- | --- | --- |
| 森林の広がり | 出典付きの淡い森林分布ラスタ／簡略化した実データ | 森林が存在する場所 |
| 木材生産 | 同年・同定義の州別データがそろった場合の面積比例円 | 州全体の生産量の違い |
| 選択地域 | 出典に対応する州境・既存地形の控えめな強調 | 解説が対象とする場所 |

森林分布を木材生産量や伐採区域として見せない。森林型・樹種の分布もそのまま人工林・商業林の範囲と見なさない。

州別の円は州内の読みやすい代表位置へ置き、「州全体の集計」であることを凡例に明示する。農場・伐採地点・工場の位置を表す記号として扱わない。円の面積を量に比例させ、半径比例にしない。ゼロと欠測は別扱いとする。

地名は選択中の説明に必要な範囲で表示する。既存の川・山地等を比較する場合は実形状を使い、線を濃くする程度にとどめる。重なり・縮尺に応じた省略を行い、全ラベルを常時追加しない。

### 地域の読み比べ

地域別の候補は「南部」「太平洋岸北西部」「北東部・五大湖周辺」。これは調査候補であり、順位・生産量・樹種・用途の結論は資料確認後に確定する。各候補に所属州・説明根拠・参照年を持たせる。解説用地域を、生産量の境界や厳密な植生境界として描かない。

根拠が確認できた地域から採用し、件数を満たすための仮データ・推測による輪郭は作らない。

## 6. 解説の構成案

冒頭キーセンテンス案：
> 森林の広がりは自然条件に支えられ、木材生産の立地は育成・管理と加工・輸送の条件にも左右される。

| 項目 | 読者に持ち帰ってほしいこと | 補う用語・確認対象 |
| --- | --- | --- |
| 森林が育つ条件 | 気温・降水・地形が森林の成立や成長に関わる | 針葉樹・広葉樹、対象地域の気候と地形 |
| 森林から木材生産へ | 森林の存在と、利用・生産の条件を分けて考える | 人工林・天然林、管理、伐採、森林面積と生産量 |
| 木材の用途 | 収穫した木材が異なる製品へ加工される | 丸太・製材・合板・パルプ等を定義し、用途別に小見出しを分ける |
| 生産地と加工・輸送 | 木を育てる場所から、加工や需要へつながる | 加工拠点、集荷・輸送。根拠のある場所だけ示す |

本文の各項目は、短い見出し・特徴を示す副見出し・キーセンテンス・説明・その場で押せる比較ボタンを必要に応じて組み合わせる。農業版の4項目を機械的に複製せず、地域差が理解できる説明にする。

森林面積、立木の蓄積、年間の木材生産量はそれぞれ面積・資源量・期間内の生産を表す。用語は初出で説明し、本文や図で混同しない。留保は誤読を防ぐために必要なものへ絞る。

## 7. 本文内の比較・復帰

| ボタン例 | 遷移・表示 | 実装条件 |
| --- | --- | --- |
| 森林と雨の分布を比べる | 自然環境の降水量へ。森林背景または対象地域を残す | 採用した森林データと座標・表示範囲が一致 |
| 地形と林業地域を重ねる | 自然環境の地形へ。説明対象の地形を強調 | 対応する既存形状・IDを確認 |
| 木材生産の地域差を見る | 同ページの生産量図へ | 比較可能な統計を確保 |
| 木材が製品になる場所を見る | 主要産業の該当する加工解説へ | 製材・紙等に対応する具体的な項目と根拠が存在 |

現在の主要産業カタログには独立した製材・紙・パルプ項目がない。初版で「その他の製造業」へ飛ばすだけの曖昧なボタンは作らない。加工の概要は林業本文で説明し、産業担当が対応項目を用意した時点で具体的な比較リンクを有効にする。

自然環境では「林業から比較中」と比較対象を明示し、元の林業解説へ戻るボタンを置く。復帰時は選択地域・カメラ・凡例の状態を復元する。比較を終えたら林業の強調が他の話題に残らないようにする。

## 8. 統計とデータ取得方針

### 確認した一次資料の入口

| 候補 | 利用目的 | この設計段階での確認範囲 |
| --- | --- | --- |
| [USFS FIA](https://research.fs.usda.gov/programs/fia) | 森林資源の面積・状態等 | 公式調査の位置付けを確認。具体的な取得ファイル・基準年・加工仕様は未確定 |
| [USFS TPO Interactive Reporting Tool](https://research.fs.usda.gov/products/dataandtools/timber-products-output-tpo-interactive-reporting-tool) | 木材製品・残材等の生産と利用 | 州・郡・年別に参照可能。新方式で処理された州から掲載する旨の注意があり、全国同年比較を前提にしない |
| [USFS TPO One-Click Factsheets](https://research.fs.usda.gov/products/dataandtools/timber-products-output-tpo-one-click-factsheets) | 州の生産・用途・一次加工施設等 | 項目の存在を確認。州別の値と対象年は取得時に検証する |

上記は取得候補の確認であり、必要な全データのダウンロード・全国整合・再配布条件の確認が完了したという意味ではない。森林分布図も、FIAの数表とは別に全国を覆う適切な公式地理データを特定し、土地被覆・森林定義・年・利用条件を確認する。

### 採用条件

1. 対象地域、対象年／調査期間、森林・生産・用途の定義、単位、欠測、出典、利用条件を記録する。
2. 木材生産量と工場の受入量、立木蓄積と年間生産、素材と加工品を分ける。
3. TPOのimports／exportsが州間移動を含む場合、それを米国の国際輸出入と表示しない。
4. 複数年をまとめた森林資源推計を、単年の生産統計と同時点の観測と見せない。
5. 体積・重量・金額の間を根拠なく換算しない。比較グラフの期間・分母をそろえる。

### 初版の図

優先するのは「森林の広がり」と「確認できた木材生産・用途」の理解である。農畜産の3列統計をそのまま流用しない。

- 同年・同定義の対象全州がそろう場合：州別生産量の地図と比較図、整合する用途構成図を最大2枠で表示。
- 全国比較が成立しない場合：州別生産量の全国地図・全国順位は出さない。確認済み地域の個別資料を対象年付きで表示し、全国合計の代用品にしない。
- 用途の合計・分類が整合しない場合：円グラフを作らず、用途の定義と流れを本文で説明する。
- 輸出先・世界シェアは初版の必須項目にしない。後で追加する際は、丸太・製材・紙等の製品範囲をそろえて別途設計する。

## 9. 状態管理・実装接点

現状の `ProductId` は作物・畜産の選択と統計をまとめて扱う。林業をそこへ足すだけでは、作物グラフ等への誤ったフォールバックが生じる。

提案する選択状態：
- `agriReading=forestry:timber`
- `forestRegion=<採用した地域ID>`（未選択時は省略）
- 既存の `agriProduct`・作物／畜産統計の値は復帰用に保持できるが、林業の統計として描画しない。
- `#forestry-timber` からの直接表示に対応する。
- `ReadingView` に林業を独立した種別として追加する。農畜産の品目列挙と森林の地域選択を分ける。

比較コンテキストは、対象種別が農畜産か林業かを判別できる形に拡張する。林業の選択・戻り先・比較対象を保持し、現在の農畜産リンクの解釈は互換維持する。既存の農業用パラメーターへ偽の作物IDを入れて回避しない。

主な実装接点：
- `src/lib/atlas-agriculture-detail-state.ts`：選択・URL・直接表示・履歴。
- `src/components/atlas/AtlasExplorer.astro`：分類UIと林業表示枠。
- `src/scripts/atlas-agriculture-details.ts`：選択・復帰・右側解説・統計切替。
- `src/scripts/atlas-agriculture-insights.ts`：比較・強調・復帰。必要に応じ共通部分へ切り出す。
- 新設候補 `src/data/atlas/forestry.ts`、`src/components/atlas/ForestryReading.astro`、専用静的アセットと出典manifest。

実装着手時に最新mainを再確認する。他担当の自然環境・産業改稿を古いファイル全体で上書きしない。共有コンポーネントへの変更は差分を絞る。

## 10. 性能・アクセシビリティ・失敗時表示

林業データは初回選択時に遅延取得し、以後はキャッシュを再利用する。タブの往復ごとに同じデータを取得・展開しない。実データから事前生成した軽量な表示用アセットを優先し、新しい地図インスタンスは作らない。

WebGLが利用できない場合も、同じ出典・範囲の代替図と解説で読めるようにする。林業データ取得失敗時は失敗対象と再読込操作を示し、作物地図を林業地図として表示しない。

ボタンはキーボード操作・フォーカス表示・44px程度以上の操作領域を確保する。色だけで森林・生産量・選択地域を区別せず、凡例・単位・名称も付ける。

## 11. 実装順序と完了条件

1. データの実物を取得し、対象範囲・年・定義・利用条件を確認。全国比較型か、地域資料型かを決定する。
2. 地域ごとの要点・定義・比較先を原稿化し、出典と対応させる。
3. 林業の独立した選択状態・本文・統計・地図を追加する。
4. 名称変更、本文内導線、自然環境への比較・復帰を接続する。産業へのリンクは対応先の完成後に追加する。
5. 通常地図／代替図、iPad相当の横幅／狭い画面、選択と復帰を確認する。実機確認の有無は別に報告する。

完了条件：
- 三分類と具体的な選択先が、開閉操作なしで分かる。
- 森林分布と木材生産の意味が凡例・本文で区別できる。
- 地図の地名、解説、本文内ボタンが対応する。
- 林業選択中に農畜産の統計が林業データとして残らない。
- 既存の作物・畜産・関係解説・共有URLを壊さない。
- 自然環境との比較から林業へ戻れ、強調・カメラ・選択状態を適切に復元できる。
- 数値が未取得の図、実体のないボタン、推定で埋めた地理データを公開しない。

## 12. 他担当への引き継ぎ

本設計の追加だけでは、他タブに作業を発生させない。林業実装時には自然環境担当と比較コンテキストの接続箇所を確認する。産業担当には、将来の製材・紙・パルプ項目が整備されたときに具体的な相互リンクを検討する。

今回の変更対象はこの設計書のみ。README・共通指針・他担当のコードは変更しない。
