## 1. 目的と合意した完成形

地図上で気候区分の分布を把握し、都市名をタップすると、その都市の雨温図と気候の特徴を一続きに読める画面にする。iPad横画面で地図と右欄を見比べることを優先する。

「各気候区分の概説」へ見出しを更新したロサンゼルス選択時の画像を、利用者が再確認し、最終承認した。本書はその配置を実装の基準として確定する。画像中の数値、コードの地理的位置、文字サイズは設計用の概略であり、実装では既存の実データとCSS pxに合わせる。

| 領域 | 表示するもの | 表示・操作の条件 |
|---|---|---|
| 左の地図 | 現行の塗り分け、都市名、詳細な気候コード | コードは都市選択やホバーを待たず表示する |
| 右欄の先頭 | 「都市の雨温図」→すぐに雨温図 | 都市選択欄、解除ボタン、独立した都市名タブを挟まない |
| 雨温図の直下 | 選択都市のコード、分類名、短い解説 | 都市選択と同時に切り替える |
| 都市の解説に続く部分 | 「気候と作物」と短い説明 | iPad横画面の同じ画面内に収まる場合に表示する |
| 地図の下 | 「各気候区分の概説」 | 初期状態は閉じる。タイトル行全体のタップで開閉する |

本書は[v2.3](./atlas-natural-environment-reading-layout-design-v2.3.md)の気候画面に関する仕様を更新する。相違する記述は本書を優先する。水資源19件・地形9件の名前操作と右欄の解説、標高表示、農業・産業等の仕様は継承する。今回の成果物は設計書である。次の「実装せよ」は本書の実装、検証、main反映、GitHub Pages公開、公開画面の確認までを含む。

### 最終承認した配置の要点

- 左に大きな地図を置き、都市名と詳細な気候コードを常時表示する。
- 右は「都市の雨温図」直下から図を始め、選択都市の気候解説、収まる場合の作物説明へ続ける。
- 地図下の「各気候区分の概説」は、閉じたタイトル行を初期表示にする。
- 都市選択欄、解除ボタン、独立した都市名タブ、長い図の注釈、「色と気候コード」の展開操作を置かない。
- 都市を選び直しても左の地図と右の解説の配置を維持し、内容だけを更新する。

今回の再確認による機能・対象範囲の追加はない。以降の仕様はこの完成形を実装可能にするための条件である。

## 3. 画面配置と文字量

### 3.1 iPad横画面：960 CSS px以上

左列を大きな地図、右列を外幅380pxを基準とする読み取り欄にする。両者の上端をそろえ、地図と欄の間隔は16pxを基準とする。左列は「地図→短い操作案内→各気候区分の概説」の順。右欄や開いた数表の高さによって、地図下に大きな空白を作らない。

右欄の順序は次のとおり固定する。

1. 見出し「都市の雨温図」。
2. 選択した都市の雨温図。都市名は図内上部の端に小さく表示する。ボタンやタブの形にしない。
3. 棒・線の凡例、単位、期間と短いNOAAリンク。図の付属情報として1〜2行に収める。
4. 気候コードと分類名。例：「Csa　地中海性気候」。
5. 細分類の特徴と、図の読み取りにつながる2〜3文。
6. コードの意味を説明する短い1行。例：「C：温帯　s：夏季少雨　a：暑い夏」。
7. 同じ画面内に収まる場合のみ、短い「気候と作物」。
8. 閉じた「月別の数値・観測地点」。観測所の正式名、標高、ID、月別値、関連する出典へ到達できるようにする。

見出しと図の間は8px程度とし、操作欄や大きな空白を設けない。図の共通軸は降水量0〜350mm、気温−10〜40℃を維持する。月、目盛り、単位は実表示12px以上、都市の解説は14pxを基準とし、収めるための極端な縮小はしない。

### 3.2 「一画面に収まる」の判定

基準は1180×820 CSS px、補助確認は1024×768と1280×800とする。通常の文字サイズ・概説と数表が閉じた初期状態で、サイト上部の共通ヘッダーを含めて、右欄の雨温図と都市の気候解説までが画面下端から16px以上内側に収まることを必須とする。

作物文は40〜70字程度・2〜3行を目安とする。右欄を通常表示した際、作物文を含む末尾まで収まる組み合わせにだけ追加する。幅だけで判定せず、画面の高さと実際の折り返しも確認する。収まらなければ作物欄を省き、全文は「各気候区分の概説」で読めるようにする。気候の説明を途中で切ったり、図を小さくしすぎたりして作物欄を押し込まない。

判定は初期配置、都市変更、画面回転・サイズ変更に対応する。利用者のスクロール位置を理由に表示と非表示を往復させない。文字拡大時は通常のページスクロールを許容し、本文を切り落とさない。右欄の固定高や独立スクロールは設けない。

### 3.3 狭い画面

960px未満は「地図・案内→雨温図と都市解説→各気候区分の概説」の一列。390×844、820×1180、横向きの844×390を確認する。スマートフォンで全要素を一画面に押し込むことは要求しない。都市解説までを優先し、作物文は折りたたみの概説から読めるようにする。

地図上の都市名は既存どおり選択可能とし、選択後の「○○の雨温図へ」リンクを地図直後に残す。このリンクを押した場合だけ右欄相当の見出しへ移動する。都市選択そのものによる自動スクロール・自動ズームは行わない。

## 4. 都市の気候解説とデータ

### 4.1 表示の単位

雨温図、都市名、コード、分類名、解説、作物文を同じ都市IDで一括更新する。前の都市の説明と新しい図が混在する中間状態を作らない。都市の気候コードは既存 `climate-cities.json` の `koppenCode` を使い、一般知識や雨温図の見た目から上書きしない。

| 都市 | 現行コード | 都市 | 現行コード |
|---|---|---|---|
| シアトル | Csb | サンフランシスコ | Csb |
| ロサンゼルス | Csa | ラスベガス | BWh |
| デンバー | BSk | ダラス | Cfa |
| シカゴ | Dfa | デトロイト | Dfa |
| ニューオリンズ | Cfa | マイアミ | Am |
| ワシントンD.C. | 欠測（null） | ニューヨーク | Cfa |

ワシントンD.C.は現行データで分類が欠測している。実装時に観測所座標・元格子・陸域マスクの対応を確認する。訂正の根拠がなければ、図は表示したうえで「気候区分：データなし」と短く示し、分類の説明と作物欄は出さない。近隣格子のコードを黙って借用しない。修正する場合は理由・根拠・変更した値を記録する。

分類は1991–2020年の既存格子、図は同期間のNOAA観測所平年値のままとする。両者の違いに関する方法説明はページ下部の出典・加工方法に保持し、右欄に長い注意書きを再掲しない。

### 4.2 原稿と出典

各都市に、既存月別値を読み取る短い文章を用意する。分類の一般的特徴と、その観測所の季節変化を区別する。同じコードの都市に同一の気温・雨量傾向を機械的に当てはめない。

ロサンゼルスの表示例：

> **Csa　地中海性気候**  
> 夏に乾燥し、夏の気温が高い型。  
> ロサンゼルスでは、夏の雨が少なく、冬に降水が集中する。雨温図の夏の低い棒と、冬の高い棒にその特徴が表れている。  
> C：温帯　s：夏季少雨　a：暑い夏

作物文の例：

> **気候と作物**  
> ブドウ・オリーブなど。カリフォルニアで栽培され、乾燥する夏には水の確保も重要になる。

分類名と色は `climate-legend.json`、作物の根拠は `climate-overview.json` の既存一次資料を再利用する。都市の説明に添える作物は周辺地域・気候との関係であり、市街地での生産を示す文章にはしない。灌漑等の必要条件は短文でも保持する。根拠のある地域例がない都市では、同じCfa等であることだけを理由に別地域の作物を割り当てず、作物欄を省略できる。

新規データは `src/data/atlas/climate-city-reading.json` を想定し、都市ID、細分類の短い説明、図の読み取り文、任意の作物文、出典参照を持たせる。コードは都市データから参照し、二重に手入力しない。文章中の分類、図の値、出典の対応を実装時に照合する。

## 5. 地図内に常時表示する詳細コード

### 5.1 見せ方

色面の特徴を直接読めるよう、Csa・Csb・BWh・BWk・BSk・Cfa・Dfa・Dfb等の詳細コードを塗り分け領域の中へ置く。コードは小さな太字と白い縁取りを基本とし、都市名の選択表示とは見た目を分ける。コードラベル自体は説明を開くボタンにしない。

同じコードが離れた地域にある場合は、地域ごとに繰り返し表示できる。全国図では主要な塗り分けの広がりを読める配置を優先する。細かな山地の区分は、拡大に応じて追加のコードを表示する。「常時表示」は、その表示範囲・縮尺で用意したコードが選択やホバーなしで見える意味であり、小さな格子片すべてへ文字を詰め込む意味にはしない。

都市名12件とコードが競合する場合は、都市の操作領域を確保し、コードの位置・重複回数を調整する。主要な別コードをまとめて消すことで解決しない。小領域で文字が入りきらない場合は短い引出線を用い、どの塗り分けを指すかを明確にする。全国図と拡大図の両方で読める文字サイズを保つ。

### 5.2 座標と配置の根拠

既存 `climate-classes.png` とmanifestの投影範囲から、コード別の地域内にラベルの候補点を事前作成する。まとまった領域の内部点を基本とし、境界からの余裕や周辺ラベルとの距離を考慮する。見た目だけで座標を手置きして終えず、候補点を元格子で再照合する。

追加ファイルは `climate-code-labels.json`、生成処理は `scripts/build-climate-code-labels.py` を想定する。レコードにはID、コード、緯度経度、地域識別子、縮尺別の優先度、必要な代替候補点を含める。コード・候補点・元格子の一致を検証可能にする。元の色面、分類値、州境を変形してラベルに合わせない。

通常地図ではMapLibreの地図内座標へ投影し、代替図では画像が実際に収まる領域と同じWebメルカトル座標を使う。v2.3で修正した地図内の相対座標による配置を継承する。ラベル文字の大きさは画面上で安定させ、地理的位置だけをパン・ズームへ追随させる。

### 5.3 軽量化と代替表示

既存のMapLibre 1個、雨温図のSVGを利用する。コードは既存ラベル制御に接続する非操作DOM群を第一案とし、都市名と共通の衝突判定を使う。ラベル集合を再利用し、パンごとにノードを追加しない。各分類の地域解析をブラウザ内で繰り返さず、通常は事前作成した候補点だけを使う。

候補点は全国・拡大を合わせて120件以内、追加データはgzip 30KB以内を目安とする。初期全国図の表示数は読みやすさから調整し、実際の表示数とコードの網羅状況を記録する。原資料やDEMの再取得、新しい地図・図表ライブラリ、外部API呼び出しは不要である。

WebGL失敗時も同じ候補点を代替地図へ重ね、都市選択とコード表示を維持する。JavaScript無効時用の図にコードを必要とする場合は、既存格子・候補点から静的派生図を生成し、操作時のラベルと二重表示しない参照先に分ける。派生資産を追加した場合はmanifestの容量とハッシュを更新する。

## 6. 「各気候区分の概説」の開閉

見出しの表記は **「各気候区分の概説」** で統一する。現在の8グループの分類名・コード・特徴・作物・条件・出典をそのまま収める。全体を単一の `details` と `summary` にし、初回とページ再読込時は閉じる。閉じた状態では見出しと開閉矢印だけを表示する。

見出し行全体をタップ領域とし、キーボードのEnter／Spaceでも開閉できる。内部にさらに項目別の開閉ボタンを重ねない。都市変更では本文や開閉状態を変更せず、同じページで別モードへ往復した場合も利用者が開いた状態を維持する。URLやブラウザの永続保存へ開閉状態を追加する必要はない。

開くと左列の幅で下へ展開し、地図や右欄を覆わない。狭い画面では都市解説の後に展開する。開閉で図や地図を作り直さず、地図位置・都市選択・フォーカスを維持する。

## 7. 選択・URL・アクセシビリティ

### 7.1 初期都市と操作

実装上の補完判断として、初回から図を読めるよう、都市未指定の場合は画像案と同じロサンゼルスを初期表示する。有効なURLの `city` 指定を最優先し、同一ページ内で記憶している都市があれば継承する。新たな端末保存は追加しない。

| 操作・状態 | 結果 |
|---|---|
| 都市名・都市点を選ぶ | 図、コード、解説、任意の作物文を同時に更新。選択した名前を強調 |
| 同じ都市を再選択 | 現在の内容を維持。解除しない |
| 都市指定なし、無効な都市ID | ロサンゼルスを表示。履歴を増やさず既存URL書式で正規化 |
| 別の自然環境タブ・分野へ移動して戻る | 都市とカメラ状態を保持して復帰 |
| 戻る／進む、共有URL | 都市、表示モード、地図位置を復元し、解説も同じ都市へそろえる |
| パン、ズーム、画面回転 | 都市を変更しない。ラベルだけを再配置 |
| Escape | 気候画面では都市を解除しない。他モードの対象解説を閉じる既存操作は保持 |

「色と気候コード」の展開・分類選択を撤去し、気候タブの解説更新を都市選択へ統一する設計判断とする。色面のタップで、選択都市と異なる地点の解説を右欄へ追加する旧動作も停止する。背景タップやコード文字のタップは都市選択を変更しない。水資源・地形・等高線の線や面の選択は既存どおり動作する。

旧URLの `natureFeature=climate:...` は独立した気候説明を再表示せず除去する。有効な `city` が併記されていればその都市を保持する。旧 `climate-table-*` の既知の都市IDは図へ引き継ぎ、未知の値は初期都市へ戻す。他モードの `natureFeature` を一括消去しない。新しいクエリ名は追加しない。

### 7.2 操作可能な名前を残す

都市選択欄をなくした後も、都市名はHTMLボタンとしてTabで到達し、Enter／Spaceで選べるようにする。既存の `aria-controls` を図と都市解説の共通領域へ関連付け、短い `aria-live` 通知で都市名と分類名の更新を伝える。気候コードの地図ラベルはTab順へ追加しない。

都市選択時に右欄へ自動でフォーカスを移さない。タップ領域は44pxを目標とし、密集部でも既存の24px以上と対象間の分離を保つ。非表示の都市パネル、撤去した選択欄、閉じた概説本文はTab順に残さない。図の読み上げ名、月別値の数表、出典へ到達する手段を保持する。

## 9. 実装と公開の進め方

1. 着手時の最新mainと他分野の変更を確認し、独立ブランチを作る。本書の確認SHAへmainを巻き戻さない。
2. 右欄の整理、都市解説、折りたたみ見出しを実装してGitHubへ保存する。
3. コード候補点を既存格子から作成・照合し、通常地図と代替図へ接続する。
4. 受入条件を確認し、修正と検証記録を保存する。異なる画面幅で成立させるために仕様変更が必要な場合は、その具体的な差分を提示する。
5. 必須CI成功と最新mainとの整合を確認して反映し、既存のGitHub Pagesで公開する。
6. 配信成功だけで終えず、公開URLで都市選択・コード表示・概説の開閉を確認し、利用者が触れるURLを提示する。

文書の優先順位は、最新の利用者指定→本書v2.4→本書と矛盾しないv2.3・既存設計とする。確認画像を理由に、他分野の共通ヘッダーや未依頼の機能まで変更しない。
