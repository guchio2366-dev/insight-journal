# 水資源：降水量・河川の流域 追加設計書 v1.0

対象：Insight Journal／北米／自然環境。作成日：2026-09-14。

状態：設計作成済み、実装前。本書では画面・データ・URL・検証の契約を定める。サイトの変更・公開は次の実装依頼で行う。

確認した公開側の基準は main `d43580295fe8cc5e91eacaffa651e63b2c85d006`。自然環境の既存仕様は [v2.5](atlas-city-climate-context-v2.5.md) と [実装記録](atlas-nature-implementation.md) を引き継ぐ。実装開始時には最新mainを再確認し、他分野の更新を取り込む。

## 1. 目的と範囲

読者が「どこにどれだけ降水があるか」と「どの範囲の水が同じ川へ集まるか」を地図から読み取り、農業・都市の水利用を考える材料にする。

自然環境の上位タブは気候区分／水資源／地形／標高（等高線）のまま。水資源の内部に次の3タブを設ける。

| 表示名 | ID | 主な表示 | 右側の解説 |
| --- | --- | --- | --- |
| 河川・地下水 | `rivers` | 既存の河川・湖・貯水池・帯水層 | 名称をタップした対象の説明 |
| 降水量 | `precipitation` | 年平均降水量の色分けと等雨量線 | 選択した降水量帯の読み方、地理的背景 |
| 河川の流域 | `basins` | 主要河川の流域面、河川線、名称 | 選択した流域の広がり・本支流の関係・水利用 |

水資源を初めて開く場合は河川・地下水。URLに指定があればそれを優先する。年・月・季節の切替、任意の河口からの流域計算、流量予測、灌漑区域や作物の同時重ね合わせは今回含めない。

## 2. レイアウトと操作

### iPad横画面

既存の2列を使い、左に大きな地図、右に解説を置く。右欄と地図の上端をそろえる。タブは水資源のときだけ表示し、地図と解説の上に1行で配置する。

| 位置 | 内容 |
| --- | --- |
| 地図の上 | 河川・地下水／降水量／河川の流域 |
| 左 | 地図、薄い州境・州名、対象名称、選択状態 |
| 地図の直下 | 短い操作案内と凡例。長い解説は置かない |
| 右上 | 現在のタブの短い概説、または選択対象の見出しと説明 |
| 右下 | 関連する農業などへのリンク、閉じた「出典・データについて」 |

「米国本土の自然環境」という共通見出しや「対象を選択」ボタンは復活させない。選択前の右欄は2〜3文の読み方を示し、空の詳細枠を並べない。選択すると同じ場所を対象の解説へ置き換える。大きな地図上ポップアップは使わない。

1024×768、1180×820を基準に、地図と主要解説を読みやすく収める。長い出典や補足は折り畳む。全文を収めるために本文を極端に縮めず、展開時はページ全体を縦に伸ばす。右欄だけの小さなスクロール枠は作らない。

### 狭い画面・入力方式

地図→凡例・案内→解説の1列。タブは折り返して横にはみ出さない。明示的に対象を選んだ場合は解説見出しへ移動できるようにし、「地図へ戻る」を付ける。履歴復元・読み込み完了だけではスクロールしない。

名称をHTMLの操作要素として提供し、タッチとキーボードで同じ説明へ到達できるようにする。フォーカスを可視化し、タップ領域は44pxを目標に配置する。線は見た目より広いヒット領域を持たせる。ホバーがないと数値・名称が読めない表示にしない。

## 3. 降水量タブ

### 地図の意味と表示

タイトルは「年平均降水量」。常時「1991–2020年平均・mm/年」と表示する。直近の天候や特定年の実績ではない。

PRISMの米国本土1991–2020年平年値・年降水量・4km格子を第一候補にする。同資料は本土48州の月別・年別の平年値と4km／800mの選択肢を提供している。[PRISM 30-Year Normals](https://prism.oregonstate.edu/normals/)

初版の区分と線は次のとおり。

| 色分けする範囲（mm/年） | 内部ID |
| --- | --- |
| 250未満 | `lt250` |
| 250以上500未満 | `250-500` |
| 500以上750未満 | `500-750` |
| 750以上1,000未満 | `750-1000` |
| 1,000以上1,500未満 | `1000-1500` |
| 1,500以上2,000未満 | `1500-2000` |
| 2,000以上 | `gte2000` |

- 等雨量線は250／500／750／1,000／1,500／2,000mm。1,000・1,500mmをやや太くし、線上に値を常時記す。その他も適切な間隔で表示する。
- 色は少雨から多雨へ明度が順序立つ配色。未取得・対象外は別の中性色で区別する。河川線は等雨量線と線色・太さ・ラベルで区別する。
- 州ごとの塗り分けや州平均への置き換えは行わない。地域内の勾配を残す。
- 全国表示ではラベルを間引き、ズーム時に追加する。細かい線の全表示より大きな分布の読み取りを優先する。

### タップと右欄

操作案内：「色分けされた地域をタップすると、降水量帯の解説を表示します。」

面をタップすると該当帯を選ぶ。線をタップした場合は、その線の値を下端とする帯へ対応付ける（1,000mm線なら1,000〜1,500mm未満）。線を選ぶ別の状態・別パネルは増やさない。右の見出しに範囲を明記し、場所の正確な観測値とは表示しない。

右欄は①帯の範囲、②分布の読み方2〜3文、③水利用・農業を考える視点1〜2文、④根拠のある関連リンクの順。全国に離れて分布する同じ帯を、一つの気候・作物地域とみなさない。原因が地域で異なる場合は地域名を添える。

降水量帯には地図上の代表ラベルを設け、同じ選択をキーボードでも可能にする。凡例は固定の読み取り用とし、クリックで全候補一覧を開く仕組みは作らない。

## 4. 河川の流域タブ

地図上の流域面と名称のどちらをタップしても同じ解説を開く。操作案内：「流域の色や川の名前をタップすると、水の集まる範囲と解説を表示します。」

流域は地表の排水範囲として扱う。帯水層の範囲、給水区域、灌漑区域、実際に全降水が河川へ流れる範囲と同一視しない。

### 初版の対象と階層

| 対象 | ID | 扱い |
| --- | --- | --- |
| ミシシッピ川 | `mississippi` | 本支流を含む全体の外縁を表示・選択可能にする |
| ミズーリ川 | `missouri` | ミシシッピ川水系の支流域として表示 |
| オハイオ川 | `ohio` | ミシシッピ川水系の支流域として表示 |
| コロラド川 | `colorado` | 全体流域 |
| コロンビア川 | `columbia` | 全体流域 |
| サクラメント川 | `sacramento` | サンホアキン川と区別する |
| サンホアキン川 | `san-joaquin` | サクラメント川と区別する |

これは主要7対象の地図であり、米国の全流域を網羅する地図ではない。対象外は薄い灰色とし「その他・今回未収録」と示す。内陸の閉鎖流域を近隣の海へ注ぐ河川に割り当てない。

ミシシッピ川全体を一つの外枠で囲み、その内側でミズーリ川・オハイオ川の支流域を薄く区別する。塗りを重ねて濃さに意味が生じないよう、表示面は重複しない区画に分ける。ミシシッピ川の名称を選ぶと全体、支流名または支流域面を選ぶとその支流域を強調する。面の選択は登録対象のうち最小の流域を優先する。

右欄は①河川・流域名、②どこからどこへ水が集まるか、③親水系・主な支流、④水利用や農業との関係、⑤関連リンク。ミズーリ川・オハイオ川には「ミシシッピ川水系の一部」と表示し、「水系全体を見る」で親流域を選べるようにする。初期状態では特定の川を自動選択しない。

### 境界データ

USGSの流域境界データ（WBD等）を候補とし、実装の最初に取得可能な版・利用条件・包含関係を確認する。設計時点では配信説明ページの取得に失敗しており、境界ファイルは未取得。特定のHUC集合を確定済みとは扱わない。[USGS WBD](https://www.usgs.gov/national-hydrography/watershed-boundary-dataset)

HUCの上位区分をそのまま単一河川の全流域と呼ばない。各対象について採用ユニット、合流点、含める支流、除外領域を対応表にし、全体流域の根拠を確認する。米国外へ続く流域は米国内表示で切れている旨を説明する。全国図を覆うために未確認の国外境界を作らない。面積の数値は完全流域／米国内部分を区別できる場合だけ掲載する。

7対象の実境界を検証できない場合は、模式ポリゴンで代用せず、取得方法・代替データと影響を提示してから範囲を調整する。

## 5. 農業との連携と説明方針

年降水量は作物の栽培可否を単独で決めない。生育期の降水、蒸発散、土壌、灌漑などを区別する。1,000mmや1,500mmの線を「小麦・稲作の栽培限界」とは記載しない。作物の必要水量は気候・作物・生育段階で変わる。[FAO Crop Water Needs](https://www.fao.org/4/s2022e/s2022e02.htm)

初版では農業から参照できるURLを先に確定する。農業側の本文・インサイトを一括改稿する作業は本書の実装範囲には含めず、別の農業担当が同じURLを使えるようにする。自然環境から既存の作物解説へ戻るリンクは、説明の根拠と既存の遷移先を確認できた箇所に付ける。

| 遷移例 | URLの状態 |
| --- | --- |
| 年降水量の全国図 | `env=water&waterView=precipitation` |
| 1,000〜1,500mm帯 | `env=water&waterView=precipitation&precipBand=1000-1500` |
| ミシシッピ川全流域 | `env=water&waterView=basins&basin=mississippi` |
| サクラメント川流域 | `env=water&waterView=basins&basin=sacramento` |

ベース経路は既存の `/insight-journal/atlas/north-america/nature/`。新規の別ページを増やさず、水資源タブ内の状態として開く。

## 6. 状態・互換性の契約

- `env=water` を維持し、新規 `waterView=rivers|precipitation|basins` を追加。未指定・不正値は `rivers`。
- 降水量選択は `precipBand`、流域選択は `basin`。上表の登録IDのみを受け入れ、不正値は未選択にする。
- 既存 `natureFeature=water:…` は河川・地下水用として保持する。旧URLに新タブ指定がないときも従来の対象解説を表示する。
- 各サブタブの選択は独立して保持し、表示中のタブの選択だけを描画する。切替時に都市・農業・人口・産業など他分野の状態を消さない。
- カメラは共有。タブ変更・対象選択だけでは勝手にパンやズームをしない。範囲外の対象は明示操作で表示範囲を合わせられる既存方式を使う。
- サブタブ・対象の明示選択は履歴に残し、戻る・進む・再読込・共有URLで同じ表示へ復元する。地図移動の途中や読み込み完了だけで履歴を増やさない。
- 農業からのリンク作成は現在のURLを複製して必要な値だけを設定する。以前の水資源選択は遷移先に合わせて解除・設定し、無関係な対象を選択しない。作物・統計・都市の状態は保全する。

## 7. 実装構成と軽量化

分析は空間分布と集水範囲の比較。描画は既存MapLibreの1インスタンスに追加し、新しい地図ライブラリ・常時API通信・3D・アニメーションは導入しない。WebGLが使えない場合は同じデータから生成した静的地図とHTMLの名称操作で同じ説明を提供する。

| 資産・処理 | 方針 |
| --- | --- |
| 降水量の色面・判定面・等雨量線 | 一つの年降水量格子から事前生成し、閾値と欠測を共有する |
| 流域面・表示用区画 | 元境界を事前結合・簡略化。親子の包含関係と隣接境界を維持する |
| 名称・解説 | 安定IDと出典を持つ小さなJSON／TypeScriptデータ |
| 配信 | 新タブを初めて開いた時だけ必要な資産を取得。既存ローダーのキャッシュ・再試行方式を利用 |
| レース対策 | 遅い旧リクエストが、切替後の地図・凡例・解説を書き換えない世代管理 |
| 代替地図 | 元データと同じ投影・表示範囲・色・名称から静的画像を生成 |

目標値は新タブ1種あたり初回追加転送1MB以下、両タブ合計2MB以下、gzip展開後のベクター合計10MB以下。これは未計測の予算であり達成済みではない。水資源以外の初回表示で新規地理資産を取得しない。

元の全国高解像度データをブラウザーへ送らず、取得・切り出し・等雨量線生成・簡略化は開発時に行う。データ取得はタイムアウト付きとし、完了済みファイルとチェックサムを保存して再利用する。巨大データの取得が停滞したら同じ要求を無期限に待たず、必要範囲取得や公式の別配布形式へ切り替える。

容量を超えた場合は、まず座標精度と形状簡略化を調整し、次に低倍率用表示を縮小する。1,000／1,500mm線や主要流域の意味を削る変更は行わない。予算超過が解消できなければ実測値と選択肢を報告する。

実装候補：`src/lib/atlas-state.ts`、`src/lib/atlas-nature-state.ts`、`src/lib/atlas-nature-loader.ts`、既存の地図レイヤー管理、`src/scripts/atlas-explorer.ts`、自然環境のAstro部品とCSS。新資産は専用ディレクトリへ隔離し、既存の気候・標高資産を再生成しない。共有ファイルは最新mainとの差分を確認して編集する。

## 8. データ採用時に残す記録

各資産に出典URL・配布版・取得日・対象範囲・期間・単位・利用条件・変換手順・原本と成果物のチェックサムを残す。降水量は格子解像度、欠測値、等雨量線の閾値を記載する。流域は元ID集合、親ID、切り出し範囲、簡略化設定を記載する。

PRISMの利用条件は公式の [Terms of Use](https://prism.oregonstate.edu/terms/) を実装前に確認する。候補ソースの採用とデータファイル取得は未完了であり、設計書の作成をもって数値・境界の検証済みとはしない。

## 9. 受入条件と作業順

1. データ採用：PRISMの年降水量1枚と主要7流域の境界を取得し、利用条件・単位・対象範囲・親子関係を検証する。ここで成立しない候補を画面実装へ持ち込まない。
2. 事前生成：色面・線・流域区画・名称・静的代替画像を生成する。境界付近と欠測、投影、海岸での切断、1,000／1,500mm線の値を元データと照合する。
3. 画面・状態：3タブ、地図選択、右欄、URL復元、農業からの直接リンクを実装する。
4. 検証：下記を確認し、既存プロジェクトのチェックを通す。
5. 公開：実装依頼にはGitHub Pages公開を含む。CIと配備成功後に公開画面・直接リンクを確認し、実機と代替表示の検証範囲を分けて報告する。

### 必須確認

- 3タブが水資源内にだけ現れ、旧URLで河川・地下水の19対象が従来どおり開く。
- 降水量の色面・線・選択帯・凡例が一致する。閾値上、欠測、海域を誤分類しない。
- ミシシッピ川全体とミズーリ川・オハイオ川の選択範囲・親子説明が一致する。表示区画に意図しない隙間・重複を作らない。
- 流域は河川線と整合し、未収録域や国外切断を流域境界と誤認させない。
- 直接リンク・再読込・戻る／進む・連続タブ切替・取得失敗後の再試行が機能する。カメラと他分野の状態が保たれる。
- 1024×768、1180×820、390×844で名称、線の値、解説が読め、横スクロールやタップ対象の重なりがない。キーボードで同じ説明へ到達できる。
- 静的代替表示でも対象名から解説が開き、GPU検証の代わりと誤報しない。気候の12都市、地形、標高、農業、産業、人口の既存動作に回帰がない。
- 資産サイズ、追加リクエスト数、切替時の読込挙動を実測する。既存の `npm run check` と公開境界検証を通過する。

実装後は本書に採用データ、変更点、検証結果、公開コミットを追記して引き継げる状態にする。

## 実装記録（2026-09-15）

- PRISM M4の1991–2020年平均・年降水量、約4km格子を採用。公式ZIPは約2.75MBで取得できた。WBDは公式ArcGIS RESTからHUC8を1回取得し、必要なユニットを結合した。配信には原本を含めない。
- HUC8の簡略化で発生する小さな穴・断片（0.002平方度未満）は除去し、採用ユニットと除外ユニットをmanifestに明記した。コロラド川のGreat Divide、サクラメント川のGoose Lake、スネーク川側の主要な地表閉鎖流域などは別扱いとした。国境で切り出した全国比較用の概略図である。
- ミシシッピ川の面は本流に集まる範囲を示し、レッド川・アチャファラヤ川側は含めない。その接続関係は右欄に明記する。オハイオ川にはテネシー川を含む。表示用の面は親から子を差し引き、親の外縁は別に保持する。
- 地図は既存MapLibreを利用し、gzip済みGeoJSONを初回だけ取得する。代替表示は同じ地理形状から生成したWebPとHTMLの選択ラベル。選択範囲も代替図上に輪郭を重ねる。
- 農業側が利用するURL生成関数は `src/lib/atlas-water-state.ts` の `waterTargetUrl`。既存の農業記事の改稿は含めず、自然環境側から既存の品目解説へのリンクを用意した。
- 自動検証では元格子の参照地点、全14ラベルの所属、国境外・閉鎖流域、親子関係の元ユニット、ファイルハッシュ、1タブ1MB以下の転送予算を確認する。データ生成は `scripts/build-water-assets.py`。元ファイルのURL・版・チェックサム・使用したHUC8一覧は公開manifestに記録する。
- 開発用URLにはクラウドブラウザーから接続できなかったため、ローカルで地図画像を検査し、画面操作を自動試験したうえで、公開後にブラウザーで表示を確認する。実機Safariの確認とは区別する。
