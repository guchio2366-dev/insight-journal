## 0. 最初に読む要約

目的は、同じ地図を見ながら「どこで何が育つか」「その場所の条件が栽培・収穫にどう作用するか」「米国農業の規模と貿易」「作物の用途と世界での位置」を順に理解できるようにすることである。

今回の設計は次の三つを一体で扱う。

1. **iPad横・PCの配置改修**：左に約3分の2の地図、右に米国農業の短い概説・農産物販売高の構成・輸出入額の推移。右欄は産地を選んでも全米の概況を維持する。
2. **地域と作物に対応する地図上の説明カード**：選択した栽培域と重要な地形を避け、短い因果説明を重ねる。iPhoneで置けない場合は同じカードを地図直下へ移す。説明を出すために地図を自動移動・自動拡大しない。
3. **作物別の解説と統計**：地図より下に、とうもろこし・大豆・小麦・綿花・米の特徴、用途、輸出先の円グラフ、世界生産シェアと推移を置く。一度に表示する作物は一つとする。地図上では全作物の分布を同時表示し続ける。

利用基盤はAstro・MapLibre GL JS・GitHub Pagesを維持する。確認済みデータを静的配信し、閲覧時の有料API、常駐サーバー、文章の都度生成を前提にしない。

**本書の優先順位**：最新のユーザー指示 → 本書の合意済み要件 → 実装時の調整値 → 旧設計・旧コードの挙動。v4.0は設計書の版であり、地理データの現在の資産ディレクトリ `v3/` を変更する指定ではない。

### 2.2 本書で置く実装初期値

以下は完成形を変えない範囲で、実画面を見て調整してよい。

- 2列の開始目安：利用可能幅1,000 CSS px以上、利用可能高さ640 CSS px以上。
- 地図：全米概況の幅比はおおむね2：1。右欄は概ね300〜380 CSS pxを確保する。
- 地域カード本文：広い画面は2〜3文、狭い画面は短い1〜2文。文字数は広い画面100〜180字、狭い画面40〜80字を目安とし、意味が欠ける場合は地図直下を使う。
- 全国の横棒は上位5品目＋その他を基本とする。比較する品目の定義は統計の取得時に確認する。
- 時系列は最新の利用可能な完結年を終点とする10年分を基本とする。
- 地図上の風の矢印・追加の気候図は拡張候補。今回の必須機能は地域原稿と、説明対象の地形等の強調である。

### 2.3 今回の完成に含めないもの

全世界への拡張、カナダ・メキシコの栽培分布、気候・土壌・主要産業レイヤーの完成、収量予測モデル、リアルタイム気象、農家・圃場単位の表示、ニュースの自動収集、サイト内の文章生成、統計の自動定期更新。

果樹・野菜の地図と既存解説は維持するが、異種品目を足した「果樹・野菜の世界生産量」は作らない。今回の作物別統計の必須対象は主要5作物である。

## 3. 画面構成と読む順序

### 3.1 iPad横・PC

| 左：約3分の2 | 右：約3分の1 |
|---|---|
| 短い分野タブ | 「米国の農業」と短い概説 |
| 米国本土の全体が収まる地図 | 農産物販売高：上位品目の横棒 |
| 地図内に選択地域の説明カード | 農産物の輸出額・輸入額：2本の折れ線 |
| 地図の凡例。カードが置けないときだけ直下に本文 | 対象年・単位・短い出典リンク |

その下にページ全幅の作物別解説・統計を置く。右欄だけをスクロールする構成にしない。ページを開いた時点で、地図全体・分野切替・全米統計2種類を読めることを受入目標にする。

地図の高さは左カラムの実幅と利用可能な高さから決める。現在の `100vw` を使った地図の高さ計算を2列配置へそのまま流用しない。比率を合わせるためにカードや統計の文字を縮めず、2列成立条件を満たさない画面では縦配置へ戻す。

### 3.2 iPhone縦・狭い画面

読む順序は次のとおり。

1. パンくず、短い分野タブ。
2. 地図全体、必要時だけ地図上に地域カード、凡例。
3. カードが置けない場合だけ、同じ選択説明を地図直下に表示。
4. 「米国の農業」の短い概説。
5. 全米の販売高・輸出入のグラフ。
6. 作物選択、選択作物の一般解説と統計。
7. 地域形成の詳述、ニュース等、展開式の出典・方法。

長い「作物の特徴と、地域に根付いた理由」の見出し、下の解説への帯状案内、繰り返しの注釈を冒頭に並べない。概説は操作説明ではなく、地図と全国統計から理解してほしい米国農業の特徴を述べる。具体的な数字・趨勢は採用データの照合後に執筆する。

全国グラフをすべて最初のスマホ画面に押し込む必要はない。地図・分野タブと、概説の読み始めを優先する。

### 3.3 分野切替

農業以外では右欄／概説欄をその分野の既存説明に切り替える。農業の販売高グラフを土地の統計であるかのように表示しない。2列の外枠と地図枠の寸法は分野間で維持し、内容の差で地図の幅・高さを変えない。

未実装分野は現在と同じく「準備中」と分かる非操作表示とする。気候・土地・産業を、農業の下位メニューへ移さない。

### 3.4 作物別解説欄

5作物の選択肢は一列または折り返しで同時に見えるようにする。閉じたプルダウンや左右に隠れたカルーセルにしない。果樹・野菜の既存解説への導線も残す。

選択作物について以下を一組として表示する。

- 特徴と適地・地域への定着理由。
- 用途説明と、比較可能な場合の用途構成図。
- 米国の総輸出量、輸出先の国別円グラフ。
- 世界の主要生産国の構成、米国の生産量・世界シェア、その推移。

地図の作物選択により下の該当作物も準備するが、タップ直後にページを自動スクロールしない。「詳しく」で下へ移動する。下の作物を切り替えても、地図上の他の作物を消さない。

## 4. 地域説明の内容設計

### 4.1 原稿の単位

原稿のキーは **`地域ID × 作物ID`** とする。州は位置の参照情報として使い、説明の境界には採用しない。

同じ作物でも、サクラメントバレーの米とミシシッピ川下流の米、南東部の綿花とテキサス西部の綿花などは説明を分ける。初期に必要な地域区分は、資料から説明可能な自然条件の違いに基づいて選ぶ。地図のすべての細片に別原稿を書く必要はない。

### 4.2 地域の判定と栽培分布の区別

既存のCDL由来の栽培分布は観測を加工した地理データとして保つ。説明の対象地域は別のGeoJSON等で管理し、「解説を選ぶための概略地域」と記録する。説明用の地域を、作物の新しい観測境界として塗らない。

選択は、タップ座標に重なる栽培域と説明地域の組み合わせから解決する。現行の米にある単一経度の分岐を、そのまま精密な地域判定として採用しない。

説明地域は資料で裏付けた地理区分を基本とし、加工方法・根拠・適用作物を記録する。境界付近、説明のない地域、凡例からの作物選択では、無理に近くの地域へ割り当てず、地域未指定の作物解説を表示する。

### 4.3 原稿の流れ

| 要素 | 書く内容 |
|---|---|
| 地域条件 | どの季節に、どの方向から、どの程度湿った空気が来るか。雨の時期、温度、土壌、水利など |
| 作物への作用 | 生育・受粉・実の形成、水不足、排水、蒸発散、作業性などにどう作用するか |
| 結果・条件 | 栽培を支える理由と、条件が崩れた場合の弱点。一般的な作用と当年の実績を分ける |

全原稿に風を必須項目として埋めない。風より灌漑や土壌の説明が重要な場所では、そちらを優先する。雨が多いほど良い、高温ほど良い、といった単調な説明にしない。年間降水量だけで判断せず、生育期・受粉期・収穫期との関係を選ぶ。

降水量等の数値を載せる場合は地域代表値・観測点・平年期間を記録する。根拠のないミリ数、特定地点の値を全地域へ一般化した数値、因果寄与率は作らない。

ここでいう単収は面積当たりの収穫量である。生産量は収穫面積にも、販売高は販売量と価格にも左右される。自然条件だけから地域の販売高を説明し切らない。

### 4.4 記述例と扱い

中西部のとうもろこしの説明例：

> 春から夏には、メキシコ湾方面からの南寄りの風が水蒸気を内陸へ運び、中西部の降水を支える。生育期に利用できる水は成長を支えるが、受粉期に高温と水不足が重なると、実のつきが悪くなり収量が落ちやすい。

この例は水蒸気輸送の研究と大学の作物解説を組み合わせた編集上の説明である。[NOAA収録研究](https://repository.library.noaa.gov/view/noaa/59778)、[Iowa State University](https://crops.extension.iastate.edu/encyclopedia/corn-pollination-effect-high-temperature-and-stress)。地域ごとの最終適用範囲は実装時に確認する。引用文の転載ではなく、出典に基づく要約である。

カリフォルニアの稲作は灌漑水の確保と平坦な土地に着目し、水不足が単収だけでなく作付面積を制約する場合も説明する。[USDAの稲作概説](https://www.ers.usda.gov/topics/crops/rice/rice-sector-at-a-glance)

原稿には通常版と短縮版を別々に保存する。短縮版をCSSの行数制限で機械的に切り落とさない。初期の執筆は実装担当が一次・公的・学術資料から行い、主張と出典の対応を点検する。

## 5. 地図上カードの挙動

### 5.1 見た目と内容

- 白に近い不透明な背景、薄い枠と控えめな影。地図が透けて本文が読みにくくならないこと。
- 地域名・作物名、短い因果説明、閉じるボタン、下の詳述へのリンクを置く。
- 同時表示は1枚。選択した範囲を輪郭等で強調する。
- 地域名のない凡例選択では、全国的な作物解説であることが分かる題名にする。
- 地図との対応が必要な場合のみ細い引出線を使う。矢印状にして風向と混同させない。
- 右の全米統計と概説は再集計も差し替えもしない。

### 5.2 配置で避けるもの

1. 選択した作物の画面内の栽培域。地域限定選択では該当地域を特に保護する。
2. 説明に必要な地理要素の範囲・ラベル。例えば水蒸気の流入元の湾、対象河川、山脈。
3. 地図の操作ボタン、分野タブ、凡例、出典表示。
4. 他の主要作物・地名。1〜3を守ったうえで重なりを減らす。

海や空白色の土地を、意味のない余白として一律に扱わない。選択した作物が広く分布し、これらの条件を満たす場所がない場合は地図直下へ移す。

### 5.3 配置手順

1. 地図のサイズと、実際に表示する本文のカード寸法を取得する。
2. 四隅・左右端・上下端など、8箇所程度の有限の候補を作る。
3. 地理座標を画面座標へ変換し、選択域と重要地形に重なる候補を除外する。判定のために元の地理座標を改変しない。
4. 残る候補から主要地名との重なり、対象からの距離、前回の位置との安定性を評価する。
5. 狭い画面では事前執筆した短縮版でも判定する。適切な候補がなければ地図直下に同じカードを置く。

判定に選択域全体の外接四角だけを用いると、離れた産地間の余白まで占有扱いになる。画面内に投影したポリゴンとカードの交差を用いる。最初は軽い既存機能または単機能の実装で足りるか検証し、必要な場合のみ小さな地理判定依存を追加・固定する。

### 5.4 安定性

本文を読んでいる間、カードが細かく移動し続けないようにする。パン・拡大開始時はカードを地図直下へ一時退避し、操作終了後に配置を再判定する。カードのための `fitBounds`・`panTo`・`flyTo` は呼ばない。

カードを閉じてもカメラは変えない。選択地域が画面外になったときは、地図外の場所に引出線を伸ばさず、直下表示で地域名を保つ。別の産地のタップは閉じてから再タップさせず、一度で差し替える。

カードの表示によって地図本体を上下へ移動させない。直下表示が現れた場合、増えるのは地図より下の高さである。iPad右欄の上端は動かさない。

### 5.5 重複する作物と小さな産地

とうもろこし・大豆の重なりは、現在の意味を保った複合作物カードとして扱う。単一作物に誤って決めつけない。下の作物別統計は直前の選択が両者のどちらかなら維持し、そうでなければとうもろこしを初期値とする。カードから両作物の詳述へ移動できるようにする。

タップ許容範囲は小画面で広げられるが、実際には領域外を押している場合や複数候補の境界では、最も近い候補を無条件に確定しない。必要時だけ小さな候補選択を提示する。拡大操作と凡例・地域選択の代替導線を用意する。

### 5.6 技術的な根拠

MapLibreには地理座標から画面座標を得る `project` と画面内地物の照会がある。[Map API](https://maplibre.org/maplibre-gl-js/docs/API/classes/Map/#project)。標準Popupの自動配置はコンテナ内に収める機能であり、本書の「栽培域と重要地形を避ける」条件は追加判定で実現する。[PopupOptions](https://maplibre.org/maplibre-gl-js/docs/API/type-aliases/PopupOptions/)

## 6. 統計の定義と表示

### 6.1 共通原則

「販売高」「生産量」「輸出額」「輸出量」「用途割合」を交換可能な数値として扱わない。グラフごとに対象品目・地域・期間・単位・母数を持たせる。

地図は米国本土、全国統計は原資料の米国集計である。アラスカ・ハワイ等の扱い、貿易の統計領域はデータ取得時に確認し、方法欄に記録する。地図の色の面積から生産量・販売高を計算しない。

### 6.2 全米の農産物販売高

| 項目 | 指定 |
|---|---|
| 表題 | 米国の農産物販売高 |
| 指標 | USDA ERSのfarm cash receipts。利益・農業GDP・作物生産量とは異なる |
| 対象 | 米国農業全体。耕種と畜産・畜産物を含むことを短く明記 |
| 期間 | 最新の完結した暦年の推計値を基本。将来予測は初期図に入れない |
| 表示 | 総販売高＋主要5品目とその他の横棒。棒の端に金額または構成比 |
| 単位 | 名目米ドル。概況は10億ドル等に統一し、日本語で単位を明記 |
| 検算 | 重複のない品目の合計が全国の農産物販売収入に一致する |

親分類と子分類を同時に加算しない。補助金・農外収入を農産物販売高に加えない。「その他」は公式総額から確認済み表示品目を差し引いて作り、その集計根拠を残す。

採用資料：[USDA ERS Farm Income and Wealth Statistics](https://www.ers.usda.gov/data-products/farm-income-and-wealth-statistics)。販売高のデータ製品と期間区分は確認済み。数値抽出・品目マッピング・検算は次工程で行う。

### 6.3 全米の輸出入動向

| 項目 | 指定 |
|---|---|
| 表題 | 農産物の輸出・輸入 |
| 指標 | 同じUSDA分類の農産物輸出額と輸入額 |
| 期間 | 最新の完結した暦年まで、連続10年を基本 |
| 表示 | 同じ金額軸の2本の折れ線。最新年の輸出額・輸入額を直接表示 |
| 補足 | 最新年の差額は小さな数値表示でよい。3本目の線や二重軸は作らない |
| 対象範囲 | 公式の農産物分類に従う。加工品等の包含範囲は方法欄に明記 |

途中までの当年実績を通年値に並べない。暦年と米国会計年度を混ぜない。名目額の増減を輸出入数量の増減と説明しない。原材料中心の作物別統計とは集計範囲が異なるため、その違いをデータ定義に残す。

採用資料：[USDA ERS FATUS](https://www.ers.usda.gov/data-products/foreign-agricultural-trade-of-the-united-states-fatus)、[更新データ](https://www.ers.usda.gov/data-products/foreign-agricultural-trade-of-the-united-states-fatus/us-agricultural-trade-data-update)。暦年・会計年度・月次の区分があるため、取得時に暦年系列を選ぶ。

### 6.4 作物の対象定義

| 作物ID | 生産で追う主対象 | 貿易等の注意 |
|---|---|---|
| `corn` | 穀粒用とうもろこし | 生食用、サイレージ、でんぷん、エタノールを生産量に混ぜない |
| `soybean` | 大豆原粒 | 大豆油・大豆ミールを大豆原粒の輸出量に足さない |
| `wheat` | 小麦粒 | 小麦粉・加工食品の重量をそのまま加算しない |
| `cotton` | 原綿（lint） | 実綿・綿実・糸・衣料を混ぜない。俵は出典の重量換算を使う |
| `rice` | 米の生産量。原則として籾ベース | 籾・玄米・精米の実重量を単純加算しない。採用系列の換算基準を明記 |

米は生産・世界シェアを同じ基準に統一する。国別貿易に公的な籾換算または精米換算系列が得られる場合はそれを用いる。得られない場合は、根拠のある換算方法を確認するか品目を明示した限定集計に変更する。限定集計を「米全体の輸出」と表示してはならない。この変更が必要なら、具体的なデータと代案を整理してユーザーへ提示する。

### 6.5 用途説明・用途構成

用途は全5作物で文章を必須とする。数値図は、同じ原材料・同じ段階で重複しない内訳を作れる場合に100%積み上げ横棒を使う。数値を分解できない場合は、割合のない用途の関係図と説明を使い、その理由を残す。

- とうもろこし：飼料・残差、エタノール原料、その他の食品・種子・工業用など。エタノールを含む上位分類とエタノールを重複加算しない。副産物が飼料になる経路は別の説明として示す。
- 大豆：原粒の搾油向け・種子等を追う。搾油で同時に得られる油とミールを「燃料か飼料か」の排他的な用途として単純に分けない。
- 小麦：食用・種子・飼料等、公式の需給表で確認できる区分を採用する。
- 綿花：原綿の繊維用途と綿実の利用を区別する。衣類別の世界用途割合を根拠なく補わない。
- 米：食用・加工等を説明する。根拠のない用途比率を作らない。

用途割合の母数は原則「米国内の当該原材料の利用量」であり、生産量ではない。輸入・在庫の存在により国内利用量と当年生産量は一致しない。内訳の残差が負になるなど100%図が成立しない系列は無理に円・帯へ変換しない。

候補資料：[Feed Grains Database](https://www.ers.usda.gov/data-products/feed-grains-database)、[Oil Crops Yearbook](https://www.ers.usda.gov/data-products/oil-crops-yearbook)、各作物のUSDA年鑑・需給表。

取得時の注意：Feed Grainsの旧Custom Queryは終了しており、現行の年鑑ファイルを使う。Oil Cropsは2026年3月に形式が更新され、個別の `Soy.xlsx` 等は継続公開されていない。古いURLを前提に加工スクリプトを組まない。

### 6.6 輸出先の円グラフ

1作物につき米国からの年間総輸出量を大きく示し、仕向国の上位5か国＋その他の構成比を円グラフで示す。国名と比率はタップなしでも読める凡例に置く。正確な数量表は展開式にする。

`国別割合 = その国向け輸出量 ÷ 同じ品目・期間・基準の総輸出量 × 100`

原則として最新の完結した暦年を用いる。販売年度の方が適切な公式系列を用いる場合は明示し、同じ図で期間を混ぜない。米国が報告した輸出データを基本にし、相手国の輸入値と都合よく混ぜない。

数量に欠測がある国を0や「その他」に置き換えない。公式総量との不一致を照合し、丸め誤差を超える場合は未確認として公開を止める。表示上の丸めによる99.9%・100.1%は注記できるが、元データの不整合を丸め誤差と呼ばない。

データ候補はUSDA FAS GATSの国別・品目別数量。現在の入口は [GATS](https://apps.fas.usda.gov/gats/default.aspx)、資料案内は[FATUS](https://www.ers.usda.gov/data-products/foreign-agricultural-trade-of-the-united-states-fatus)。具体的な品目コード・取得ファイルと数量カバー率は未照合である。

### 6.7 世界生産シェアと推移

世界生産はFAOSTATの作物・畜産物生産統計を第一候補とし、USDA PSDを照合・代替候補とする。1本の系列の途中で、出典・品目・籾／精米などの基準を変えない。

同じ年・同じ品目定義で、米国と世界合計を取得する。

`米国の世界生産シェア = 米国の生産量 ÷ 世界の生産量 × 100`

表示は「米国生産量・世界シェアの短い数値」「主要生産国とその他の構成を表す100%横棒」「米国シェアの10年推移」を一つの統計ブロックにまとめる。世界合計・地域合計・個別国を重複加算しない。米国が上位国に入らなくても米国を個別表示する。

近年の傾向は、原則として系列の最初の3年と最後の3年の平均シェアを比較し、「直近3年平均は初めの3年平均よりXポイント上昇／低下」と記す。表示精度で差が0となる場合は「ほぼ横ばい」とし、統計的有意性や将来予測を示す表現はしない。10年分揃わない場合は実在する年だけを示し、期間と欠測を明記する。

候補資料：[FAOSTAT](https://www.fao.org/faostat/en/)、[FAOの生産統計案内](https://www.fao.org/statistics/events/events-detail/agricultural-production-statistics-2010-2025.-december-2025-update/en)、USDA FAS PSD。FAOSTATとPSDは年・収穫物基準・推計方法が一致するとは限らない。PSDの取得方法は実装時に現行案内を再確認する。

### 6.8 グラフの共通表示規則

- 数量・金額の棒は0から始める。輸出入の2本の線は同じ軸・同じ期間を使う。
- 世界シェアの推移は単位を%とし、軸の範囲を明示する。小さな変動を急変に見せる極端な切り取りを避ける。
- 表示値は概数を基本とし、元の精度をデータと展開表に残す。
- 凡例・ラベルは色だけに依存しない。輸出・輸入は線種や直接ラベルでも区別する。
- 年・期間、単位、出典リンクは図の近くに表示。詳細な計算方法は展開式とする。
- 国別円グラフの色は地図の作物色と異なる役割であることを凡例で示す。作物色を国の固定色として流用しない。

## 7. データ準備・更新の契約

### 7.1 保存するメタデータ

統計系列ごとに少なくとも次を保存する。

| 項目 | 内容 |
|---|---|
| ID | データセット・系列・作物の安定したID |
| 出典 | 提供者、資料名、公式ページ、取得したファイルのURL |
| 時点 | 取得日、資料の公表／改訂日、値の対象年・期間 |
| 定義 | 原資料の品目コード、品目名、指標、単位、集計地域 |
| 基準 | 暦年／販売年度／会計年度、原粒／原綿／籾／精米等 |
| 状態 | 公表実績、推計、予測、欠測。元のフラグも保存 |
| 加工 | 抽出条件、国・品目の対応表、換算係数と根拠、計算式 |
| 再現 | 加工スクリプトの版、入力ハッシュ、出力ハッシュ |
| 利用条件 | 出典ごとのライセンス・再配布条件・表示義務 |

### 7.2 準備の順序

1. 公式のダウンロード資料と定義を確認する。
2. 必要な国・品目・年を抽出し、入力ファイルと加工記録を保存する。
3. 合計、内訳、単位、期間、予測フラグを検算する。
4. 正規化したJSON／CSVを作り、原文の数値と抜き取り照合する。
5. その値から読み取れる範囲で概説・トレンド文を執筆する。
6. 確認済みのデータと原稿を同じ改修で配信する。

元の世界全件データをブラウザへ送らない。大きな元ファイルは配信対象外で保管し、再取得可能なら公式URL・条件・ハッシュで再現できるようにする。小さな抽出済みデータと変換手順はリポジトリに残す。

### 7.3 更新と欠測

閲覧時に外部統計APIへ問い合わせない。手動または担当モデルによる更新時に同じ手順を再実行する。定期更新の自動化は別作業とする。

更新元の取得に失敗した場合は、最後に確認済みの値を対象年付きで維持する。初めから確認できていない値に0やダミー値を入れない。統計の一部が欠けても地図や原稿を巻き添えにしない。

## 8. 状態・URL・操作の契約

### 8.1 分けて管理する状態

| 状態 | 用途 |
|---|---|
| 分野 | `overview / agriculture / land`。準備中分野は遷移対象にしない |
| カメラ | 中心経度・緯度・倍率 |
| 表示モード | `fit / custom`。全体表示とユーザーが拡大した状態を区別 |
| 地図の作物選択 | 単一作物、既存の複合作物、未選択 |
| 地域選択 | 説明地域ID、未指定 |
| 下の統計作物 | 主要5作物のいずれか。地図上の色分けとは独立 |
| カード位置 | 地図内の候補位置／地図直下。URLへ保存しない |

全米概況には作物フィルターを持たせない。カード位置は端末によって変わるため復元データにしない。

### 8.2 URL方針

既存の分野パスと `lng / lat / z / crop` は互換性を保つ。追加候補は `region / stats / view`。具体的なキー名は実装時に一本化する。

例：`/atlas/north-america/agriculture/?crop=rice&region=sacramento-valley&stats=rice&view=fit`

`region` は実在する原稿・地域IDだけを許可し、作物との組み合わせを検証する。不正・古いIDは破棄して一般的な作物解説へ戻す。任意の文字列をHTMLとして挿入しない。

古いURLにカメラがあり `view` がない場合は `custom` として尊重する。新しい `fit` 状態は端末の大きさに合わせて全体を表示する。現在の `writeAtlasState` が削除する `zone / insight / place` を不用意に新しい用途へ再利用しない。

### 8.3 操作ごとの結果

| 操作 | 結果 |
|---|---|
| 地域をタップ | 原稿と対象域を選択。カード配置を判定。全国欄・カメラは維持 |
| 別の地域をタップ | 1回でカードを差し替え。下の対応作物も準備 |
| 凡例をタップ | 地域未指定の作物解説。特定地域の原稿を推測して出さない |
| カードの詳述リンク | 対応作物を表示し、地図より下の該当解説へ移動 |
| 閉じる・Escape | カードと地図選択を解除。全国欄・カメラ・下の統計作物は維持 |
| 分野を切替 | 地図の層・分野説明を切替。カードを閉じる。位置・倍率と地図寸法は維持 |
| 地図を拡大・パン | `custom` とし、説明選択を保持。操作後にカード位置を再判定 |
| 全体を押す | `fit` に戻し対象地域全体を収める。カード位置を再判定 |
| 端末回転・幅変更 | `fit` は新しい枠へ収め直す。`custom` は中心・倍率を維持 |
| 戻る・進む・再読込 | 分野・地域・作物・カメラを復元し、端末に合わせてカードを再配置 |

分野切替は履歴を追加し、パン・倍率や連続する選択変更は原則として現在の履歴を更新する。細かい操作ごとに戻る履歴を増やさない。URL復元中の `moveend` が復元途中の選択でURLを書き換えないよう、状態の確定後に保存する。

### 9.2 データモデルの最低要件

以下は型の契約を説明する例であり、アプリに実装済みのコードではない。

```ts
type CropId = 'corn' | 'soybean' | 'wheat' | 'cotton' | 'rice' | 'specialty';
type StatCropId = Exclude<CropId, 'specialty'>;

interface RegionalInsight {
```

国別内訳には安定した国IDと母数ID、用途内訳には加工段階と母数IDを加える。グラフが扱う具体値と、読みやすく丸めた表示文字列を区別する。

### 9.3 描画・性能

地図はページ内で1インスタンスを共用する。分野変更・作物選択のたびに `new Map` や `setStyle` で全体を作り直さない。

統計はAstroで生成するSVGとHTMLの表を第一候補とする。少数の棒・円・折れ線に新しいWebGLや大型ダッシュボードライブラリを加えない。必要なインタラクションは作物選択・表の展開を中心にする。

地図を使えない状態でも統計は独立して表示できるようにする。統計のためにMapLibreの読み込み完了を待たない。生データ、出典、原稿は検索・JavaScript無効時にも読めるHTMLを持たせる。

追加の統計・地域原稿データは圧縮後100KB以内を初期予算とし、上回る場合は理由と圧縮・分割の効果を確認する。カードの交差計算は選択変更・操作終了・実寸変更時に行い、全地域の計算を毎フレーム繰り返さない。既存MapLibre本体の容量は追加予算と混同しない。

## 10. 代替表示とアクセシビリティ

### 10.1 地図を描画できない場合

現在の自己配信の代替図を維持する。元の画像のピクセル座標や旧SVGタップ領域を正確な地理データとして流用しない。

代替図では、位置判定が検証できていないのにタップ可能な地域地図として見せない。凡例・展開式の地域選択から原稿を読み、説明カードは地図直下で表示する。位置のない説明を地図上の特定地域に結びつけたように置かない。

### 10.2 JavaScript・統計の障害

JavaScript無効時は各作物へ進む通常のリンクと、静的な本文・SVG／表で読める構成にする。動作しないボタンを残さない。JavaScriptによる作物切替が使える場合にだけ、他作物欄の折りたたみを有効化する。

統計ファイルだけが未取得・不整合の場合は、当該図の欠測理由と確認済みの原稿を示す。無関係な地図をエラー状態にしない。公開時の欠測は完了報告に明記し、全統計完成と報告しない。

### 10.3 操作・読み上げ

- 選択カードはモーダルにしない。表示のたびにページ全体のフォーカスを奪わない。
- 閉じる、詳述、作物選択はタップ・キーボードで操作できるようにする。主要操作の目標サイズは44 CSS px程度とする。
- 本文は原則14px以上、グラフの主要ラベルは12px以上を初期値とし、実際のiPhoneで読めることを確認する。
- カードの読み上げは選択変更時だけに行い、カード移動やカメラ移動のたびに同じ文章を繰り返さない。
- 地図上カードと地図直下カードを別々に読み上げさせない。単一の表示内容・状態を共有する。
- 選択作物名、年、値、単位を文字でも示し、色やホバーだけで情報を伝えない。
- 文字拡大・画面回転・動きを減らす設定を尊重する。文字拡大時の地図直下表示を許容する。

### 12.2 公開手順

現行の公開は `.github/workflows/pages.yml` のmainへのpushで起動する。`npm ci`、単体試験、ビルド、静的成果物の試験、公開物検証を経てGitHub Pagesへ配置する。古いrunbookにある「検証のみで公開未有効化」の記述を現在の状態と誤認しない。

実装時は既存のブランチ／PR運用に合わせ、競合と最新の差分を確認する。公開が依頼範囲に含まれるときだけ反映し、成功したActionsと公開 `_release.json` のコミットを照合する。設計書の保存だけを、サイトへの実装・公開完了と報告しない。

### 12.3 完了報告に必要な内容

確認URL、iPad・iPhone相当の画像、採用データと対象年、販売高・数量・換算の定義、主な検証結果、実機／エミュレーションの区別、残った制約を簡潔に示す。統計が一部未確認なら、地図やレイアウトが完成していても未確認部分を明記する。

## 13. 調整可能な点と、変更時に相談する点

| 実装担当が判断する点 | 完成形が変わるため相談する点 |
|---|---|
| 2列の閾値、余白、カード幅、グラフの凡例位置 | 全米概況を作物別に置き換える |
| 根拠が同等の公式データの選定・取得形式 | 輸出先を数量から金額へ切り替える |
| 確認済みの最新完結年の選択 | 原材料から加工品中心の統計へ変える |
| カードの候補位置・安全域・交差判定方法 | 主要5作物の統計を削除・恒久保留する |
| 本文の意味を維持する短縮・出典欄の整理 | 州単位の塗り分けへ戻す |
| 小さな単機能ライブラリの採否とバージョン固定 | 有料API・常駐サーバーを導入する |

風の矢印を実装する場合は、季節を明示した概略の水蒸気輸送として根拠と形状を記録する。矢印を当日の実測風として扱わない。今回の完了を、未合意の追加レイヤー作成で遅らせない。
