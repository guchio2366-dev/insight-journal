## 1. 目的と今回決めること

公開済みの自然環境を基点として、合意済みの7改修を小さな単位で復旧する。各段階は、作成したコードの保存とその段階に必要な確認までを一つの作業とする。利用者が段階ごとに成果を確認し、次へ進められるようにする。

v2.0の機能要件と地理・統計上の意味を維持し、本書では再開基点、作業順序、段階別の完了条件、保存方法を更新する。旧設計の「未確定なデータ候補」は中断記録の採用先で具体化するが、消失した成果物の正しさや利用条件を確認済みとみなさない。旧設計に残る当時の公開・実装状況は現在の状況と区別する。

今回の成果物は本設計書だけである。次の実装単位は第1段階とする。「進めて」「実装して」と指示された場合は、その時点の未完了の次段階を対象にし、段階末に結果と次の範囲を提示する。利用者が複数段階・全体の実行を明示した場合は、その範囲まで進める。同一段階内の軽微な修正や保存に確認を繰り返さない。

開始時に最新mainと共用ファイルの変更を確認し、独立した実装ブランチ・作業コピーを用意する。比較用コピーのGit参照が壊れている場合は最新mainから取得し直す。失われた `45ef7f4` の探索は、判明している保存先・コミット・参照可能な差分の確認に限る。見つからない差分を待たず、公開版のコードと設計から必要な変更を再構築する。

最初の小さな実装変更をGitHubへコミットし、返されたコミットと内容を確認してから作業を広げる。本設計書の保存で確認できるのはテキスト文書の保存経路であり、新規バイナリの転送や画面確認の成功まで意味しない。バイナリ転送は必要になる第3段階の冒頭で小さな実ファイル1件を使って確認する。

### 第2段階：都市の近くに雨温図を置く

目的は、都市と雨温図の対応を地図上で読めるようにすることである。新しい気象データの取得は不要である。

既存のNOAA1991–2020年平年値、12か月、降水量0–350mm、気温−10–40℃の共通目盛りを使う。都市点の上下左右から近い配置を選び、点と図の間隔12–24pxを目安にする。端でずらす場合は引出線を使う。別の都市の近くへ無関係に配置しない。

iPhoneでは幅200–240pxを目安に小型SVG図を置き、「大きく見る」で地図直下に詳細図・月別表・観測所情報を開く。12か月、両軸の単位・目盛りを省略しない。図とラベルを一緒に再配置し、選択点、表示中の都市名、主要操作を隠さない。

選択都市が画面外に出たら近接図を隠して選択を保持し、「都市へ戻る」を明示する。この操作を押したときだけ地図を移動する。閉じる・拡大・縮小・履歴復元は同じ選択状態を使う。

配置方式は自然環境の都市カードに限定し、農業・産業の共通カード処理を一括置換しない。小型図でも都市近接と可読性を両立できない画面が判明した場合は、確認画像と代案を示す。都市名の間引きや地図下だけの表示へ無断で変更しない。

完了条件：全12都市についてiPhone・iPad縦横・PC相当幅で配置を確認し、図・名称・選択点・操作の重なりを解消する。v2.0のA05–A08およびA01–A04の回帰を確認する。第1段階の名前の操作と統合し、コミットと実際に確認した画面を保存する。

### 第3段階：標高の淡い色付け

目的は、全国500m等高線を維持したまま低地と高地を見分けやすくすることである。

残存する3DEP由来DEM16件を既存記録と照合し、必要な処理を順次行う。全国の再取得や100m・250m等高線の再生成を開始条件にしない。照合不能・欠損があり大容量の取得が不可避なら、その時点で必要量と代案を提示する。

最大1,600×970画素を目安に、低地のクリーム色から高地の淡い黄土色・茶色へ変化する画像を作る。色は標高値に対応させ、陰影の明るさから作らない。既存線と同じ投影・範囲を使い、海域と欠測を透明にする。0m未満の陸地は残す。

凡例は全国共通の0・500・1,000・2,000・3,000・4,000mを含め、負の標高と最高域の扱いを記す。標高表示の初回だけ読み込み、線・主要線・標高ラベルを色の前面へ置く。代替図にも同じ色と線を反映する。

完了条件：v2.0のA23–A25を満たす。ロッキー・アパラチア・中央平原・海岸で色と線の位置を照合し、新規画像とメタデータを350KB以内にする。原DEM・詳細等高線は公開成果物へ入れない。生成手順とハッシュ、配信コード、画像をGitHubに保存する。

### 第4段階：年降水量500・1,000mm線

目的は、水資源と農業分布の比較に使える降水量の情報を追加することである。

採用先は中断記録で使われたPRISMの米国本土1991–2020年平年値・年間格子とする。記録された配布ZIPには月別資料を含む可能性があるため、URLの語句だけで年間値と判断せず、内部の年間合計格子、単位、期間を確認して使う。年間格子1種類だけを処理し、全国の月別・日別取得へ作業を広げない。

中断記録の原資料ZIPは2,752,139 bytes、SHA-256は `054ee0ea81f38eb2f4d4272b9a6c3905d0df1c0b92bb4e391ebc3f9901ce3246` である。残存ファイルまたは再取得物を照合し、異なる場合は同一資料として扱わず、版・内容の差を確認する。このZIPの全量転送は公開用コード保存の前提にしない。

元格子から500・1,000mmの等値線を生成し、距離座標で簡略化してから配信用座標へ変換する。初期の簡略化許容差2km、調整上限4kmをv2.0から継承し、欠測・山地・海岸で妥当性を確認する。全国用gzip GeoJSONを一度だけ配信し、ブラウザで線を生成しない。

線は薄い紫の破線と数値ラベルにし、水資源の初回表示で入、利用者が切替可能にする。今回の復旧版は基本2本だけを採用し、v2.0の任意候補1,500・2,000mmは追加しない。実際の等値線を西経100度の直線や12都市の補間で代用しない。

1,000mm線を小麦栽培の限界線と説明しない。年降水量の地域差を読む線として扱い、農業との説明では生育期の水分、気温、土壌、灌漑を区別する。面のPRISM推定値と都市観測所のNOAA平年値は別のデータであることを出典欄で示す。

完了条件：v2.0のA12–A15を満たす。元格子と西部山地・大平原・南東部を照合し、代替図でも入／切が働く。固有メタデータ込みの圧縮合計400KB以下、展開JSON2MB以下、座標数40,000以下。データ・生成手順・出典・ハッシュ・操作を保存する。

### 第5段階：土壌分布と作物との関係

目的は、地形・気候・水分とともに土壌の特徴を比較できるようにすることである。

中断記録の採用先はPurdue Universityの `WLD_Soil_Orders` 配信で、USDA／Reich & Eswaranの2005年広域図に由来すると記録されている。実装時に配信元、分類属性、範囲、一般化の程度、利用条件を確認し、確認できるものを使う。圃場単位の精度があるとは扱わない。

色と選択判定を同じ分類データから作る。最大1,600×970画素を目安とする色PNG、ID PNG、凡例を基本とし、IDは最近傍で扱う。同じ分布と分類を保つ小さいポリゴン形式への変更は可とする。土壌を入れた初回だけ取得する。

表示名を「地形・土壌」へ変更し、「土壌を重ねる」の初期状態は切とする。入れた時は地形陰影を弱めるが、9地形名は残す。名前の選択は地形カード、それ以外の土壌面は土壌カードを開く。

| 説明の重点 | 原分類との関係・注意点 |
|---|---|
| 草原の暗色土 | Mollisolsを入口に特徴を説明するが、全域をチェルノーゼムと呼ばない |
| 赤黄色の強風化土 | Ultisolsの酸性・養分溶脱・管理条件を説明する |
| ポドゾル化した土壌 | Spodosolsの溶脱・集積を説明し、冷涼地域に限定しない |
| ラトソル等 | Oxisolsとの関係は用語の補足とし、米国本土の主要分布を創作しない |

重点外の原分類も凡例に残し、海域・欠測・その他を分ける。カードは教育用の説明、原分類、主な分布、特徴、作物との関係と条件、出典の順とする。作物との関係に根拠がない場合は推奨作物を割り当てず、確認できた利用や制約を記す。

完了条件：v2.0のA16–A20、A22を満たす。画面とタップ分類、土壌入／切、地形名との選択優先順位を確認し、色・ID・凡例・固有メタデータを合計800KB以内にする。全国のSSURGO等を大量取得する方向へ拡大しない。適切な配信元を確定できない場合は第1〜4段階を保持し、土壌の不足点と代案を報告する。

### 第6段階：統合確認と公開の完了

目的は、完成した7改修が既存の農業・畜産・主要産業と共存し、端末上で利用できることを確認することである。

最新mainとの差分を確認し、追加された他分野の変更を作業枝へ統合する。変更した箇所の確認と `npm run check`、CIを実行し、v2.0の全34受入条件を段階別の結果へ対応付ける。合格件数そのものは固定目標にしない。

WebGLが使えるブラウザ、WebGLを使わない代替表示を別々に確認する。画面幅は390×844、820×1180、1180×820、1280×800 CSS pxを基準とし、とくにiPad横で地図・右欄・雨温図が読めることを確認する。12都市の選択、気候・地形・土壌の選択、戻る／進む、農業・畜産・主要産業との往復を確認する。

4表示を各50回往復する確認は、状態・ローダーが揃った時点で一度実施する。途中の各小コミットで全件を反復しない。未解消の具体的な不具合がある場合だけ、その範囲を再実行する。

公開は、その時点の利用者の指示範囲に沿ってPRマージと配信を行う。既に対象を含めて公開が許可されていれば重ねて確認しない。配信成功、公開URL、対象機能の到達確認を記録して「公開済み」とする。実機Safariが使えない場合は未確認と明記し、CSS幅の確認やモック試験で代替したとしない。使用可能なWebGL画面の確認にも失敗した場合は、代替図の成功だけで全完了とはしない。

| `src/lib/atlas-style.ts` | 標高色、降水量線、土壌のsource・layer |
| `src/components/atlas/`と関連CSS | 操作、雨温図、凡例、説明、代替図、フォーカスと画面幅対応 |
| `scripts/`・自然環境データ | 必要分だけの生成、出典・加工条件・ハッシュの記録 |

追加状態は `precip=on/off`（既定on）、`soil=on/off`（既定off）、`chart=compact/expanded`（既定compact）、`natureFeature=soil:<id>` とする。実装した段階でのみ有効にする。旧経路 `climate/`・`land/`、都市・地形・標高のURL、既存農業の関係選択と主要産業の状態を保持する。不正値だけを正規化し、地図位置や他分野の選択まで初期化しない。

自然環境の任意データ取得は共通キューで最大2件、同じ要求は同じPromiseを共有する。成功した全国資産は各1個を保持し、タブ往復・パン・ズームで再取得・再解析・再setDataしない。古い応答は現表示を上書きさせず、失敗は再試行可能にする。20秒のタイムアウト、一時通信失敗の自動再試行は最大1回を初期値とする。404や壊れたデータを反復取得しない。

気候初期表示で降水量・土壌・標高色・等高線を先読みしない。分類画像のID抽出後は一時RGBA・Canvas等を解放し、必要な8bit ID配列を保持する。圧縮ファイルの小ささだけでメモリ使用量を評価しない。

| 計測対象 | 設計上限・確認方法 |
|---|---|
| 気候初期HTML・JS・CSSの増分 | 圧縮合計150KB以下。今回の基準版との差分を同じ条件で測る |
| 降水量 | 圧縮400KB、展開JSON2MB、座標40,000以下 |
| 土壌 | 色・ID・凡例・固有メタデータ合計800KB以下 |
| 標高色 | 画像・固有メタデータ合計350KB以下 |
| 代替画像 | 新規・更新画像の正の増分合計450KB以下 |
| 自然環境の公開資産 | 基準版からの正の増分合計2.0MB以下。削除による相殺で超過を隠さない |
| 実操作 | 読込後200ms以内を目標に選択応答を測る。未測定の保証値とはしない |

単位は10進KB・MB。段階別増分と基準版からの累計を分け、同じファイルの更新を重複計上しない。ファイル容量、初回／再表示の実通信量、展開時間、計測可能なメモリを区別する。

## 6. 保存・検証・中断の扱い

### 6.1 保存単位

第1段階の最初の小変更からGitHub保存を行う。以降は、名前の操作、配置処理、描画用資産など、意味のあるまとまりができた時点でコミットする。段階末まで1個のローカルコピーだけに置かない。

原資料ZIP全体のアップロードを、コード・公開用派生物の保存の前提にしない。既にGitHubにある公開資産と詳細62ファイルは既存Blobを再利用する。新規の派生物は必要な段階で必要分だけ保存し、原資料のURL・対象期間・ハッシュ・処理手順も残す。転送経路は認証情報を使えるものだけを利用し、失敗した方法を繰り返し試さない。

段階の成果はPRまたは明示したブランチに残し、次段階はその保存済みコミットを基点にする。未マージの段階を含む場合は依存元を記録する。文書保存や段階のコード保存を、そのまま本番公開と扱わない。

各段階に記録する項目は、基準commit、実装要件、変更ファイル・生成手順、保存commit／PR、必要な検証結果、容量の累計、未確認事項、次の段階に絞る。転送状態は未送信／Blob登録済み／ブランチに反映済みを区別し、コミットから内容を読めた時点で保存済みとする。生の会話・非公開Notion情報・認証情報は公開リポジトリへ含めない。

### 6.2 各段階の完了の表し方

| 状態 | 意味 |
|---|---|
| コード保存済み | 対象変更・必要な派生物がリモートコミットから復元できる |
| 自動確認済み | 保存した版で、その段階に必要な試験・ビルド等が通った |
| 画面確認済み | 対象の表示と操作を実際のブラウザで確認し、環境と範囲を記録した |
| 段階完了 | 上記の必要条件と段階固有の条件を満たした。残る実機等の制約を明記した |
| 公開済み | 対象commitの配信と公開URLでの到達を確認した |

プレビューが使えない場合は、第1段階の開始時点で制約と使用可能な確認経路を明らかにする。ローカルURLの拒否を同じ方法で何度も試さない。通常URLで実画面が見られない状態では、コード保存を先に完了し、画面確認が残ることを報告する。既存の公開ページを復旧版のプレビューとして扱わず、指示なく未完成の改修を本番へ出して検証しない。

### 6.3 調査や検証を広げる条件

データ採用の再確認は判明済みの配信元から始め、同じ失敗が続く場合は理由を記録して別経路の根拠を確認する。新たな候補探索は1データ源につき20分を目安に区切り、採用条件を満たせないまま全国詳細データへ拡大しない。転送の1件が失敗した場合も、その原因を解消する前に大きなバッチへ進まない。

各段階で影響する試験を行い、段階末に既存の必要な検査を実行する。完全な繰り返し操作・全端末の確認は第6段階へ集約し、途中では変えた操作・データ・配置を中心に確認する。確認済み事項の反復は、具体的な回帰リスクが生じた場合に限る。

文字や図を読めなくする縮小、対象都市名の間引き、近接図の地図下への全面移動、基本の降水量2本の削除、土壌の実分布を手描き模式図へ変更すること、対象地域や有料サービスの追加は、代案と影響を示して相談する。意味を保つ圧縮・簡略化・ラベル移動・既存Blobの再利用は実装側で判断する。

## 7. 他分野との共存と公開判断

v2.0の設計保存基点 `1b37e2e` から今回の `abe7627` までには、主要産業のラベル調整と農業の関係解説・供給用途図が追加されている。`atlas-explorer.ts`、`AtlasExplorer.astro`、`atlas-state.ts`、`atlas-style.ts`、関連CSSは共用変更があるため、古いファイル全体を復元して上書きしない。現在のmainへ必要な自然環境差分だけ適用する。

段階開始時と統合時に最新mainを確認する。他の変更が追加されていた場合は実際の共用差分を読んで取り込み、選択・カメラ・URL・カードを確認する。保存は自然環境用ブランチで行い、mainの強制更新や既存作業枝の上書きは行わない。

公開対象は、完了条件を満たした段階のコミットで固定する。段階単位で公開する指示がある場合は、その段階で動く機能だけを公開し、後続段階の操作を出さない。まとめて公開する場合は第6段階で行う。公開後に問題が出た場合は、その段階の変更を戻す通常のrevertを使い、他分野の変更や保全済み資産を消さない。

## 8. 次回の開始点

次は第1段階に着手する。最初に最新mainと利用可能な保存・画面確認経路を確認し、都市・気候・地形の名前による操作を復旧する。第1段階の終点は、そのコードのリモート保存と必要な確認結果の提示である。第2段階以降のデータ加工を一緒に始めない。

第1段階の完了報告は「できるようになった操作／保存先と確認結果／未確認事項と次の第2段階」の3点にまとめる。
