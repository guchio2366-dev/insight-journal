## 1. 目的と今回決めること

公開済みの自然環境を基点として、合意済みの7改修を小さな単位で復旧する。各段階は、作成したコードの保存、その段階に必要な確認、本番公開と配信確認までを一つの作業とする。利用者が段階ごとに成果を確認し、次へ進められるようにする。

本改訂では、利用者のiPad横画面での確認を受け、R02を「米国本土の自然環境」欄への都市雨温図の組み込みに変更する。旧案の都市近接カード・小型図と詳細図の二重構成を置き換える。v2.0のその他の機能要件と地理・統計上の意味を維持し、配置に連動する状態・操作・受入条件は本書を優先する。旧設計の「未確定なデータ候補」は中断記録の採用先で具体化するが、消失した成果物の正しさや利用条件を確認済みとみなさない。旧設計に残る当時の公開・実装状況は現在の状況と区別する。

今回の成果物は設計文書の修正だけである。他のエージェントが作業中のため停止したコード変更・main反映・本番配信は、本依頼では再開しない。次の実装単位は改訂後の第2段階とする。以後「実装して」と指示された場合は、その時点の次段階について検証・PR反映・本番公開・配信確認まで進め、公開URLと次の範囲を提示する。利用者が複数段階・全体の実行を明示した場合は、その範囲まで進める。同一段階内の軽微な修正や保存に確認を繰り返さない。

### 第2段階：「米国本土の自然環境」欄に都市の雨温図を組み込む

目的は、選択した都市の雨温図を一定の場所で読み、地図の気候分布と見比べられるようにすることである。利用者がiPad横画面で確認した読みやすさを採用理由とする。既存の12都市・NOAA1991–2020年平年値・SVG図を使う表示変更であり、新しい気象データの取得・加工は不要である。

#### 4.2.1 挿入先と内容の順序

挿入先は `NaturalEnvironmentSummary.astro` の `[data-natural-summary]`、その中の `[data-nature-summary-panel="climate"]` とする。見出し「米国本土の自然環境」と短い導入文に続けて、次の順序で表示する。

1. 小見出し「都市の雨温図」と都市選択リスト。
2. 選択都市名、観測所名、雨温図。未選択時は「地図の都市名、または一覧から都市を選択してください。」の短い案内。
3. 凡例、1991–2020年、NOAA出典、観測所標高。既存の月別値の選択と「月別の数値・観測地点」の展開操作。
4. 「気候区分の概説」と既存の短い説明文。「同じ場所を農業で見る」は欄の末尾に残す。

既存の上部ナビゲーションにある都市選択リストを、この欄へ移す。都市名・点から選ぶ操作も維持し、地図上とリストの選択値を同期する。都市選択リストを上下に重複させない。最初から特定都市を自動選択せず、有効な `city` を含むURLではその都市を復元する。

表示する雨温図は常に選択した1都市分である。既存の12都市分の図は使い回してよいが、表示・アクセシビリティ上で有効な図は1枚にする。図の見出しでも都市名を明示する。現行CSSには図内の都市名を隠す指定があるため、移設先で都市名が消えないように修正する。

#### 4.2.2 画面幅による配置

| 画面 | 地図と雨温図欄の配置 | 確認すること |
|---|---|---|
| iPad横・PC（原則960 CSS px以上） | 左に既存の地図、右に「米国本土の自然環境」欄。その欄内の上部に雨温図を置く | 地図と図を同じ画面内で見比べられ、雨温図が地図・都市名・操作に重ならない |
| iPad縦・iPhone（原則960 CSS px未満） | 地図・凡例に続けて、同じ「米国本土の自然環境」欄を1列で配置 | 雨温図は欄の幅を使い、別の小型図や横スクロールを必要としない |
| 画面回転・幅変更 | 同じ都市選択・同じ図を保ったまま、CSSで2列／1列を切り替える | 図・都市選択リスト・IDを複製しない。選択都市、月別詳細の開閉、キーボードのフォーカスを可能な限り維持する |

960pxは現行の自然環境欄のブレークポイントを初期値として使う。2列時の右欄は外幅340〜400px程度、図の実描画幅は300px程度以上を目安にする。月・両軸の目盛り・単位は実表示で12 CSS px以上を確保する。図は縦横比を保ち、12か月、降水量0–350mm、気温−10–40℃の共通目盛りを維持する。都市ごとの自動伸縮や文字の縮小で詰め込まない。

都市の選択・解除で列幅や地図枠の寸法を変えない。雨温図欄は通常の文書内に置き、独立したスクロール枠や高さ固定による切り落としを設けない。長い観測所名は折り返し、月別表の展開時はページ全体を縦に伸ばす。iPad横の初期確認では月別表を閉じ、地図と図の全体が見える配置を優先する。

iPad横・PCでは都市選択によるページの自動スクロールをしない。1列時も勝手にスクロールさせず、都市選択後は地図直下に「○○の雨温図へ」の短いリンクを出し、押した場合に欄の見出しへ移動できるようにする。

#### 4.2.3 選択・解除・他の説明との関係

| 操作・状態 | 動作 |
|---|---|
| 都市名・都市点・都市選択リスト | 同じ都市選択処理で欄内の図・都市名・選択値・地図上の強調を更新する。開いている気候面の説明は閉じる。地図の中心・倍率・ページ位置は変えない |
| 同じ都市を再選択 | 同じ雨温図を保持する。選択解除の代用にはしない |
| 気候面を選択 | R03の気候帯の説明を既存の共通選択カードで開く。欄内の都市雨温図と都市の選択記憶は保持する。地点の気候区分と都市の観測値を同一対象として表示しない |
| 気候面カードの閉じる操作・海域等の選択 | 気候面のカードだけを閉じ、都市雨温図を消さない。欠測を補完しない |
| 「都市の選択を解除」またはリストの未選択項目 | `selectedCity` とURLの `city`、都市の強調を解除し、短い未選択案内へ戻す。他分野の状態や気候面の選択は解除しない |
| Escape | 共通選択カードが開いていれば先にそのカードを閉じる。カードがなく、気候表示の地図・都市名・都市選択・雨温図欄を操作中の場合は都市選択を解除する。非表示の都市選択を他タブから解除しない |
| 水資源・地形・標高・他分野へ切替 | 雨温図欄を非表示にし、選択都市を記憶する。気候区分へ戻ると同じ都市の図を復元する |
| 選択都市がパンで画面外へ移動 | 都市名は第1段階のルールで隠すが、欄内の図は表示し続ける。「都市へ戻る」を押した時だけ地図を移動する |
| WebGLが使えない | 同じ欄・同じSVG図を使う。代替地図の都市名・点・リストのどこから選んでも更新する |
| 戻る／進む・共有URL | `city`、自然環境の表示、地図位置、農業・産業の状態を一貫して復元する。幅変更・パン・図の配置だけで履歴を追加しない |

都市選択の解除後は選択元へフォーカスを戻す。元の都市名が画面外・非表示の場合は欄内の都市選択リストへ戻す。更新は短い `aria-live` 通知で知らせる。都市選択・解除・「都市へ戻る」等は44pxの操作領域を基本とする。

雨温図は概説欄の常設要素、気候面等の共通選択カードは一時的な説明として分離する。共通カードは1枚までとし、常設雨温図との同時表示を認める。都市雨温図のために地図内の共通カードを開かず、旧カードと欄内の図を二重表示しない。都市名と地点の引出線は維持するが、地図と右欄を横断する線は追加しない。

#### 4.2.4 実装接続と後方互換

- `NaturalEnvironmentSummary.astro` に都市選択・雨温図の配置先を設ける。必要なら自然環境専用の部品へ分ける。
- `NatureViewNavigation.astro` から都市選択リストを移設する。4表示のタブ、水資源・地形の選択操作は維持する。
- `AtlasExplorer.astro` の共通選択カードから都市用の図を移し、`ClimateDiagram.astro` の同じデータ・出典・月別表を再利用する。
- `atlas-explorer.ts` の都市選択・復元処理を専用の欄更新へ接続する。現在の `hideSelection`・`closeSelection`・`restoreSelectionForView` が雨温図まで一括で隠さないよう責務を分ける。都市の強調も気候面カードの開閉から独立させる。
- 雨温図は共通カードの位置計算・`selectedCoordinate`・カード用フォーカス操作から分離し、都市用の「都市へ戻る」と選択元を持つ。既存農業・産業・地形・水資源のカード配置を一括変更しない。
- 自然環境のラベルDOM・座標・選択イベントとMapLibre1インスタンスを再利用する。雨温図の位置を求める投影・衝突計算、新しい可視化ライブラリ、気象データ取得を追加しない。

### 第3段階：標高の淡い色付け

目的は、全国500m等高線を維持したまま低地と高地を見分けやすくすることである。

残存する3DEP由来DEM16件を既存記録と照合し、必要な処理を順次行う。全国の再取得や100m・250m等高線の再生成を開始条件にしない。照合不能・欠損があり大容量の取得が不可避なら、その時点で必要量と代案を提示する。

最大1,600×970画素を目安に、低地のクリーム色から高地の淡い黄土色・茶色へ変化する画像を作る。色は標高値に対応させ、陰影の明るさから作らない。既存線と同じ投影・範囲を使い、海域と欠測を透明にする。0m未満の陸地は残す。

凡例は全国共通の0・500・1,000・2,000・3,000・4,000mを含め、負の標高と最高域の扱いを記す。標高表示の初回だけ読み込み、線・主要線・標高ラベルを色の前面へ置く。代替図にも同じ色と線を反映する。

完了条件：v2.0のA23–A25を満たす。ロッキー・アパラチア・中央平原・海岸で色と線の位置を照合し、新規画像とメタデータを350KB以内にする。原DEM・詳細等高線は公開成果物へ入れない。生成手順とハッシュ、配信コード、画像をGitHubに保存する。

### 第4段階：年降水量500・1,000mm線

目的は、水資源と農業分布の比較に使える降水量の情報を追加することである。

採用先は中断記録で使われたPRISMの米国本土1991–2020年平年値・年間格子とする。記録された配布ZIPには月別資料を含む可能性があるため、URLの語句だけで年間値と判断せず、内部の年間合計格子、単位、期間を確認して使う。年間格子1種類だけを処理し、全国の月別・日別取得へ作業を広げない。

中断記録の原資料ZIPは2,752,139 bytes、SHA-256は `054ee0ea81f38eb2f4d4272b9a6c3905d0df1c0b92bb4e391ebc3f9901ce3246` である。残存ファイルまたは再取得物を照合し、異なる場合は同一資料として扱わず、版・内容の差を確認する。このZIPの全量転送は公開用コード保存の前提にしない。

元格子から500・1,000mmの等値線を生成し、距離座標で簡略化してから配信用座標へ変換する。初期の簡略化許容差2km、調整上限4kmをv2.0から継承し、欠測・山地・海岸で妥当性を確認する。全国用gzip GeoJSONを一度だけ配信し、ブラウザで線を生成しない。

線は薄い紫の破線と数値ラベルにし、水資源の初回表示で入、利用者が切替可能にする。今回の復旧版は基本2本だけを採用し、v2.0の任意候補1,500・2,000mmは追加しない。実際の等値線を西経100度の直線や12都市の補間で代用しない。

1,000mm線を小麦栽培の限界線と説明しない。年降水量の地域差を読む線として扱い、農業との説明では生育期の水分、気温、土壌、灌漑を区別する。面のPRISM推定値と都市観測所のNOAA平年値は別のデータであることを出典欄で示す。

完了条件：v2.0のA12–A15を満たす。元格子と西部山地・大平原・南東部を照合し、代替図でも入／切が働く。固有メタデータ込みの圧縮合計400KB以下、展開JSON2MB以下、座標数40,000以下。データ・生成手順・出典・ハッシュ・操作を保存する。

### 第5段階：土壌分布と作物との関係

目的は、地形・気候・水分とともに土壌の特徴を比較できるようにすることである。

中断記録の採用先はPurdue Universityの `WLD_Soil_Orders` 配信で、USDA／Reich & Eswaranの2005年広域図に由来すると記録されている。実装時に配信元、分類属性、範囲、一般化の程度、利用条件を確認し、確認できるものを使う。圃場単位の精度があるとは扱わない。

色と選択判定を同じ分類データから作る。最大1,600×970画素を目安とする色PNG、ID PNG、凡例を基本とし、IDは最近傍で扱う。同じ分布と分類を保つ小さいポリゴン形式への変更は可とする。土壌を入れた初回だけ取得する。

表示名を「地形・土壌」へ変更し、「土壌を重ねる」の初期状態は切とする。入れた時は地形陰影を弱めるが、9地形名は残す。名前の選択は地形カード、それ以外の土壌面は土壌カードを開く。

| 説明の重点 | 原分類との関係・注意点 |
|---|---|
| 草原の暗色土 | Mollisolsを入口に特徴を説明するが、全域をチェルノーゼムと呼ばない |
| 赤黄色の強風化土 | Ultisolsの酸性・養分溶脱・管理条件を説明する |
| ポドゾル化した土壌 | Spodosolsの溶脱・集積を説明し、冷涼地域に限定しない |
| ラトソル等 | Oxisolsとの関係は用語の補足とし、米国本土の主要分布を創作しない |

重点外の原分類も凡例に残し、海域・欠測・その他を分ける。カードは教育用の説明、原分類、主な分布、特徴、作物との関係と条件、出典の順とする。作物との関係に根拠がない場合は推奨作物を割り当てず、確認できた利用や制約を記す。

完了条件：v2.0のA16–A20、A22を満たす。画面とタップ分類、土壌入／切、地形名との選択優先順位を確認し、色・ID・凡例・固有メタデータを合計800KB以内にする。全国のSSURGO等を大量取得する方向へ拡大しない。適切な配信元を確定できない場合は第1〜4段階を保持し、土壌の不足点と代案を報告する。

実装の順序は、表示先の分離、都市・気候面の状態分離、2列／1列とフォーカス、対象操作の検証、本番反映・配信確認とする。データ加工は不要である。第3段階以降は一緒に始めない。

完了報告は「できるようになった操作／公開URLと確認結果／未確認事項と次の第3段階」の3点にまとめる。本依頼は設計書の修正なので、この実装順序を今すぐ実行するものではない。
