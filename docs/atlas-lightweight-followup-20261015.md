## クラウドブラウザとsandbox

ユーザーPC、ユーザーのブラウザ接続、保存済みユーザープロファイルは使っていません。インストール済みの `/usr/bin/chromium`（151.0.7922.173）を、クラウド環境の承認付きexecから起動しました。通常の制限付きexecはSUID helperの設定エラーで起動しなかったためです。OS設定、helperの所有者・権限は変更していません。

```js
await chromium.launch({
  executablePath: '/usr/bin/chromium',
  headless: true,
  chromiumSandbox: true,
  env: {
    ...process.env,
    XDG_CONFIG_HOME: '/tmp/insight-chromium-config',
    XDG_CACHE_HOME: '/tmp/insight-chromium-cache'
  },
  ignoreDefaultArgs: ['--unsafely-disable-devtools-self-xss-warnings']
});
```

`ignoreDefaultArgs` はXSS警告を無効にするPlaywright既定引数を**除去**する指定です。`--no-sandbox`、`--disable-setuid-sandbox`、`--disable-gpu-sandbox`、`--disable-web-security`、証明書エラー無視などは指定していません。CDP `Browser.getBrowserCommandLine` でも禁止引数が空であることを検証しました。

`chrome://sandbox` の実測表示は Layer 1=`Namespace`、PID namespaces=`Yes`、Network namespaces=`Yes`、Seccomp-BPF=`Yes`、TSYNC=`Yes`。Chromiumは「adequately sandboxed」と報告しました。生の診断文は再測定JSONに含まれます。

全サイトE2Eの各既存ブラウザ起動には、`NODE_OPTIONS` のimportで `scripts/qa-sandbox-browser.mjs` を読み込ませています。これはsandbox無効指定や危険な追加引数を拒否し、同じsandbox・一時設定ディレクトリ・XSS警告維持の起動方法を適用し、CDPで再確認して起動ログを保存する検証用フックです。サイトの実装や配信物には入りません。

全サイト実行と基準再現を合わせて13回の起動記録があり、全て `chromiumSandbox:true`、禁止引数なしです。元のブラウザケースは機能やアサーションを変更せずに実行しました。sandboxを無効にする再試行、証明書例外、ユーザーPCでの実行は行っていません。
