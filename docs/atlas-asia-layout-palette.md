# アジア画面と北米画面の配置・気候配色の統一

2026-09-27。対象は東アジア、東南アジア、南・中央アジアの4分野です。

## 設計と変更範囲

北米と同じ `AtlasWorkspaceFrame`、`atlas-desktop.css`、`atlas-explorer.css` を使い、アジア側で重ねていた列幅・地図の縦横比・画面幅による切替の指定を取り除きました。地域選択と国選択を2段にし、その下にニュース、分野タブ、地図、解説を置きます。自然環境の主題は北米と同じ書式のボタンで選択し、アジアにある6主題を維持します。小画面ではボタンを2列に並べます。農林業・産業・人口の選択欄にも同じ枠線・背景色・高さを使います。

Astroが文書構造を生成し、既存のアジア制御処理が主題と選択状態を更新します。MapLibreの地図は引き続き1ページに1個です。地域、国、都市、主題、地図位置、比較前の状態をURLに保持する処理は維持しています。ボタンは選択状態を `aria-pressed` で伝え、TabとEnter/Spaceで操作できます。通信失敗時の再試行と位置図による代替表示も維持しています。

この変更では共通CSS、ニュース部品、欧州のページ・制御処理を編集しません。欧州のPR #116で変更した10ファイルとの重複はありません。

## 気候の色とデータ

北米の `scripts/refine-atlas-nature.py` の `climate()` が定義する全30区分の配色を使用します。北米に現れない区分も同じ定義から得ています。公開済みの北米凡例23区分とも照合します。例としてAfは `#529ca5`、BWhは `#e6ad7b`、Cfaは `#98bba0`、Dfaは `#b7c2d8` です。

`scripts/atlas_asia_climate_palette.py` は北米の生成処理を実行せず、構文木から色と記号の定数を読み取ります。既存の分類IDを格納した圧縮格子から3地域のPNGを再生成し、全画素の対応を確認します。凡例とTypeScriptの表示定義も同時に生成します。地図の不透明度は北米と同じ1です。

1991–2020年の分類、格子、対象範囲、欠測、都市観測値は変更していません。旧v1は原資料の配色を記録した基準資料としてそのまま保存しています。現行v2のmanifestに、参照する北米配色・凡例・生成器のSHA-256を記録します。1km原本から再生成する `atlas-asia-climate-detail.py` も同じ配色処理を呼びます。

配色だけを再生成する場合は、NumPyとPillowのあるPythonで `python scripts/atlas_asia_climate_palette.py` を実行します。旧v1の生成器は当時の定義も書き出すため、その再生成後は現行v2の生成処理も実行してください。

## 検証記録

1280×720の実ブラウザーで北米と東アジアを比較しました。ニュース欄はx=20・y=181.67・幅243.20、分野タブはx=279.20・y=215.67、地図はx=279.20・y=316.33・幅592.42・高さ382.20で一致しました。解説欄の開始位置と幅も一致します。本文の長さと右欄のスクロール範囲は地域の内容に応じて異なります。

390×844、1024×768、844×390でも文書の横方向のはみ出しがないことを確認しました。東京の雨温図の選択、再読み込みによる復元、Spaceでの主題切替、履歴での復帰、米の分布との比較、比較前の都市・地図位置への復帰を確認しました。

自動検証では北米の30色と公開凡例、元の分類定義、PNGと分類値の対応、出典・加工記録のハッシュ、3地域×4分野の初期表示、URL状態と比較復帰を照合します。

全体検査は単体249件成功・既存1件省略、ページ検査117件成功、ビルドと配信検査が成功しました。欧州PR #116の統合後にも再ビルドし、アジア・欧州の画面検査7件と配信検査が成功しました。3地域間の移動、東南アジアの流域切替、南・中央アジアの産業ページの欄幅も実ブラウザーで確認しました。
