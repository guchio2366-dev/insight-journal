## 現状の判定と修正

公開版の描画は既に選択分野でフィルターされていた。問題は地図内の大きな産業選択ボタン（資源10・製造12・サービス5）、広域を横断する注記用引出線、採掘・加工の地点集合を分けない重複だった。

- 産業選択ボタンは地図外の既存一覧だけにする。地図内の産業操作ボタンは0。
- 分野別に異なる地点集合・注記・記号凡例を構成。1つの地理基図と描画面を再利用するが、分野変更時には分野専用sceneへ全置換し、他分野の点・注記・案内線を残さない。地図名と `data-map-sector` も更新。
- 地図内注記は各分野最大4つ、短い非操作の産業地域名。背景の大きな付箋と産業名からの引出線を撤去。狭い画面で近くに収まらない注記は無理に遠方へ移さず省略し、完全な産業名・色の一覧は地図外に残す。
- アルミ：資源地図はボーキサイト採掘、製造地図は精錬・アルミナ。リン：資源地図は鉱石採掘、製造地図は肥料加工。鉄鋼・DRIは製造業へ。精製燃料、死海の採取・加工、ホウ素の採掘・加工は根拠のある複合工程として両分野に掲載。
- 同一産業・同一国・近接地点を画面スケールに応じてまとめる。基点は必ず既存の根拠付き座標。合算するのは掲載地点の個数だけで、生産・能力・企業売上を合算しない。本社と工場は同じ記号へ混ぜない。
- 異なる産業の記号の衝突は元位置から最大20px以内で固定配置。小点と短い灰色線で元位置を示し、流通・取引線は作らない。
- 配置入力は分野・画面サイズ・手動カメラのみ。産業・国・個別地点の選択、単独表示、解除では位置を再計算しない。
- 資源側のアルミ採掘地図へ、別工程である一次アルミ生産値の国別色・棒を使わない。製造業のリンは既存のDAP生産値、鉄鋼・DRIは既存のDRI生産値を国の色・棒へ使う。鉱石・粗鋼・一次アルミ等の全統計は表に保持し、工程の違いを明記。産業ボタンと説明見出しも表示工程に合わせる。

## 共通UI担当への契約・受け渡し

共通ファイルの変更はなし。必須の共有変更もない。選択UIを統合する場合は以下を保持する。

- 分野入力：`[data-wi-sector]`（resources / manufacturing / services）。表示分野：SVGの `data-map-sector`。
- 産業名は `westIndustryMapLabel(industry, sector)` を使う。資源側のボーキサイト、製造側のリン酸肥料・DRIなど、同じデータ系列でも表示工程に応じた名称・説明がある。
- 産業入力：地図外の `[data-wi-picker="分野"] [data-wi-industry="ID"]`。旧 `[data-wi-label]` の地図内ボタンは廃止。
- 注記：非操作の `[data-wi-annotation]`。ポイント：`[data-wi-point]`、掲載元の索引：`data-wi-members`。複数地点の記号を選ぶと産業の概説、個別地点は右欄一覧から選べる。
- 注記と地点の配置関数へ選択状態を渡さない。国別数値は元の年・製品段階で扱い、採掘/精錬等の工程を跨いで転用しない。
- 地域固有のブラウザ検証スクリプトも地図外ボタンへ更新済み。通常Chromeのある環境で `REVIEW_CHROME_PATH=/path/to/chrome node scripts/verify-west-asia-industry.mjs` を実行できる。
