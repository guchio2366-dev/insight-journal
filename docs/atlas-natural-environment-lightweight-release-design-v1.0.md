# Insight Journal 北米アトラス：自然環境タブ 軽量公開版設計書 v1.0

作成日：2026-09-13
状態：設計承認済み・実装済み・公開前
対象：`guchio2366-dev/insight-journal`／自然環境タブ
基準：実装PR #21、コミット `e1490e34ee3f03a5506fcfa5fb49223c0a450845`
元設計：`docs/atlas-natural-environment-design-v1.0.md`

## 0. 結論

自然環境タブの公開版では、標高表示に**全国共通の500m間隔等高線だけを使用する**。地図を拡大しても250m・100m間隔へ切り替えず、全国ファイルを再利用する。気候区分、水資源、地形、標高（等高線）の4表示、12都市の雨温図、海流、選択カード、農業との位置・選択状態の共有は維持する。

作成済みの250m・100m間隔データ62ファイルは削除しない。公開ディレクトリから、ビルド成果物に含まれない保全用ディレクトリへ同じ内容・同じBlob SHAで移す。これにより、利用者の追加通信とGitHub Pagesの公開物を減らし、将来の詳細表示に再利用できる状態を保つ。

本書は元設計のうち、等高線の縮尺別切替、配信対象、読込方式、性能条件を置き換える。それ以外は元設計とPR #21の実装を維持する。本書の承認後、取得済みデータを再生成せずに軽量版を実装した。

## 1. 現在地と前提

| 項目 | 確認済みの状態 |
|---|---|
| 実装 | PR #21に4表示、12都市の雨温図、海流、状態保持、代替図まで実装済み |
| 転送 | 対象125ファイル、約28.34MBはGitHubへ転送済み。手元とGitHubのBlob SHAが全件一致 |
| 検証 | 57件の単体試験、6件の動作・静的成果物試験、ビルド、公開境界検証、PRのCIが成功 |
| 公開 | PR #21はopen・未マージ。自然環境の新実装はGitHub Pagesへ未公開 |
| 実機確認 | iPhone・iPad Safariの実地確認は未完了。検証環境ではWebGLを使用できなかった |

現在の全国等高線は、USGS 3DEPを水平500m格子へ間引いたDEMから生成した500m間隔の線である。圧縮ファイルは1,469,767バイト、展開後のGeoJSONは約8.50MB、32,268フィーチャ、247,241座標を含む。

地域詳細は250m間隔31ファイル、100m間隔31ファイルである。圧縮状態では合計24,093,925バイト、展開後のJSONは合計約111.45MBである。現実装は表示範囲と倍率に応じて必要なファイルだけを読むが、取得済みPromiseを上限なしのMapへ保持し、同一画面で必要な地域ファイルを`Promise.all`で同時に開始する。

## 2. 目的と判断基準

本変更の目的は次の3点である。

1. **公開までの作業を短くする。** 取得・加工済みデータを再生成せず、転送済みBlobを再利用する。
2. **iPad・iPhoneの負荷を抑える。** 拡大時の追加通信、複数JSONの展開、長時間操作後のキャッシュ蓄積をなくす。
3. **自然条件を見比べる機能を保つ。** ロッキー山脈とアパラチア山脈の高さの差を、全国共通の基準で読める状態を残す。

初版の主目的は全国・地域間の比較であり、登山、測量、谷筋の詳細確認ではない。この目的なら、500m間隔の全国線でも西部の2,000〜3,000m級の広がり、東部の主に500〜1,000m級の起伏、中央部の低起伏を比較できる。拡大時の250m・100m線は有用だが、公開初版の必須機能から外す。

## 3. 公開時の機能仕様

### 3.1 維持する機能

| 機能 | 公開版の扱い |
|---|---|
| 気候区分 | Beck et al.の1991–2020年分類を維持。都市選択と地点分類も維持 |
| 雨温図 | NOAA平年値による12都市、共通目盛り、月別数値、観測所情報を維持 |
| 水資源 | 河川・湖・貯水池・主要帯水層の表示と選択を維持 |
| 地形 | 地形陰影と山脈・高原・平原の名称・選択を維持 |
| 標高 | 全国500m間隔の等高線、1,000mごとの主要線、標高ラベル、線選択を維持 |
| 共通表示 | カリフォルニア海流、メキシコ湾流、代表的湧昇域を維持 |
| 分野間移動 | 地図位置、倍率、選択地域、都市、農業・畜産の状態保持を維持 |
| 代替表示 | 各表示のWebPと静的な雨温図・数値表を維持 |

### 3.2 標高表示の変更

- 等高線タブを初めて選んだ時だけ`public/assets/atlas/nature-v1/contours.geojson.gz`を取得する。
- 初期の気候区分、水資源、地形、農業を閲覧するだけなら、等高線GeoJSONを取得しない。
- 地図をパン・ズームしても、`contour-tiles.json`や`contours/250/`、`contours/100/`へ通信しない。
- 読み込んだ全国GeoJSONは一つのPromiseと一つのMapLibre sourceとして再利用する。失敗したPromiseだけを破棄し、「再試行」で同じ全国ファイルを再取得できる。
- すべての倍率で補助線を500m間隔、主要線を1,000m間隔として表示する。拡大時は線幅と標高ラベルの衝突回避だけを調整し、線自体を追加しない。
- 標高値は0mと500mの倍数を公開URLの正規値とする。未公開の詳細版でだけ生成された100m・250m単位の選択値は、復元時に選択解除する。地図位置と倍率は維持する。
- 凡例と概説は「全国図は500m間隔。拡大しても同じ線を表示する」に統一する。「拡大すると250m、100m」という記述を残さない。
- 500mは**等高線の標高差**であり、鉛直精度ではない。元DEMは水平500m格子へ間引いた全国比較用データであることも出典欄に残す。

### 3.3 読込中と失敗時

等高線の取得・展開中は、作成済みの`contour-fallback.webp`を表示し、「全国の等高線を読み込み中」と示す。失敗時も同画像を残し、再試行ボタンを表示する。他の自然環境表示や農業への移動を妨げない。

代替画像は293,910バイトである。通常のMapLibre表示が成功した後に重複して画像を画面へ残さない。ブラウザがWebGLまたはgzip展開に対応しない場合も、標高の全体像と下部の説明を読める状態にする。

## 4. データの公開範囲と保全

### 4.1 公開ディレクトリに残す標高資産

| パス | 用途 | 現在のサイズ |
|---|---|---:|
| `public/assets/atlas/nature-v1/contours.geojson.gz` | 全国500m間隔の対話型等高線 | 1,469,767 B |
| `public/assets/atlas/nature-v1/contour-fallback.webp` | 読込中・失敗時の代替図 | 293,910 B |
| `public/assets/atlas/nature-v1/manifest.json` | 公開資産の出典・範囲・ハッシュ | 更新対象 |

`public/assets/atlas/nature-v1/contour-tiles.json`と、`public/assets/atlas/nature-v1/contours/`以下の62ファイルは公開物から外す。これにより、Pagesの静的成果物は詳細等高線と索引を合わせて約24.10MB減る。

### 4.2 詳細データの保全先

詳細データは次へ移す。

```text
data/derived/nature-v1/contours-detail/
├── contour-tiles.json
├── 250/
│   └── 31 files
├── 100/
│   └── 31 files
└── manifest.json
```

移動時は内容を変換・再圧縮しない。既存のGitHub Blob SHAをtree作成時に再利用し、62ファイルのバイト列を再送しない。保全用`manifest.json`には、旧公開パス、新保全パス、間隔、範囲、バイト数、Git Blob SHA、SHA-256を記録する。

公開用`manifest.json`の`files`には、実際に`public`へ存在するファイルだけを載せる。標高欄の`contourIntervalsM`は`[500]`へ変更し、詳細版の存在と保全マニフェストへの相対パスを、配信機能と誤認しない名称で記録する。

取得原資料、加工前DEM、生成スクリプト、停止時アーカイブは保持する。通常のサイトビルドと軽量化実装では、USGS・NOAA等への再取得を行わない。

## 6. 通信量・描画負荷の設計値

「サイトを最初に開く」「等高線タブを開く」「地図を拡大する」を分けて評価する。

| 操作 | 標高関連の通信 | ブラウザ側の処理 |
|---|---:|---|
| 自然環境ページを気候区分で開く | 0 B | 等高線の取得・展開・描画なし |
| 等高線を初めて開く | 約1.47MB | gzipを約8.50MBのGeoJSONへ展開し、32,268線をMapLibreへ設定 |
| 等高線を再度開く | 0 B | 保持済みの全国データとsourceを再利用 |
| パン・ズーム | 0 B | 同じ線の再描画とラベル配置だけを行う |
| 読込失敗時の代替図 | 約0.29MB | WebP画像一枚を描画 |

これらは標高関連の値であり、共通HTML、JavaScript、MapLibre、気候画像、地形画像等を含むサイト全体の通信量ではない。gzip展開後サイズはJavaScriptオブジェクト化後の実メモリ量でもないため、iPadで実測する。

軽量公開版では、実行時キャッシュに地域別キーを作らない。したがって、長時間パンしても等高線データの保持件数は一件から増えない。全国ファイルの解析自体がiPadで重い場合に備え、0.29MBの代替画像へ切り替えられる失敗経路を維持する。

## 7. 開発・転送方式

実装はPR #21のコミット`e1490e34...`を起点とする。ローカルの`04cd0e1...`はファイル内容が一致する別履歴であるため、履歴全体を強制pushしない。

1. 既存の取得・加工済みデータとSHA台帳を使う。大容量データを再生成しない。
2. 62件の詳細Blobは既存SHAを新しい保全パスへ割り当てる。ファイルごとのBase64再送を行わない。
3. 変更する少数のコード、文書、マニフェストだけを登録し、既存treeを基礎に一回のtree作成へまとめる。
4. PR #21のブランチを、現在のheadが想定どおりであることを確認してから更新する。
5. CIと端末確認が済むまでmainへ統合しない。

この方式により、開発時の大容量処理を避けると同時に、GitHub Pagesへ毎回含まれる公開成果物も減らす。詳細データはGitリポジトリ内に残るが、Astroの`dist`には含めない。

## 9. 検証手順

### 9.1 自動検証

- ローダー試験：最初の等高線要求、同時呼出しのPromise共有、再表示、失敗後の再試行を確認する。
- ネットワーク境界試験：倍率3、5、7と複数地域へのパン後も、全国ファイル以外の等高線要求が発生しないことを確認する。
- データ試験：全国gzipを展開し、FeatureCollection、標高値、ハッシュ、ファイル上限を検証する。
- 保全試験：62ファイルのパス、サイズ、Git Blob SHA、SHA-256を保全マニフェストと照合する。
- 公開境界試験：`dist`に詳細資産が存在しないことと、削減バイト数を確認する。
- 回帰試験：4表示、12都市、カメラ保持、URL、農業・畜産、代替表示を確認する。
- 最終ゲート：`npm run check`とGitHub CIを実行する。

元CSV144か月や気候分類の再検算は、関連ファイルのハッシュが変わらないことを確認した上で既存結果を継承する。軽量化と無関係なデータ取得・加工を繰り返さない。

### 9.2 画面・端末確認

実機またはWebGLを使用できるブラウザで次を確認する。

1. 気候区分から等高線へ移ると、代替図から対話型線へ切り替わる。
2. ロッキー山脈とアパラチア山脈の標高差を同じ凡例で比較できる。
3. ズーム7まで拡大しても追加通信がなく、500m間隔であることを誤認させない。
4. 線のタップ・クリックで標高カードが開き、カードが対象と主要操作を隠さない。
5. iPad横では左地図・右概説、狭い画面では地図・カード・概説の縦並びになる。
6. 等高線から気候へ戻ると12都市の選択と雨温図が復元される。

全国GeoJSONの読込時間、展開時間、描画開始までの時間、取得バイト数は端末と回線条件を添えて記録する。数値目標を事前に捏造せず、実測後にQA記録へ載せる。

## 10. 実装順序と停止条件

実装を再開する場合は次の順に進める。

1. PR #21のheadと保存済みSHA台帳を照合する。
2. 詳細資産を同じSHAで`data/derived`へ配置し、公開treeから外す。
3. ローダー、状態、凡例、概説、マニフェストを500m固定へ変更する。
4. 影響する単体・動作・公開境界試験を更新する。
5. ローカルゲートと端末確認を行い、結果を実装記録へ追記する。
6. 少数の変更ファイルをPR #21へ反映し、CIを確認する。
7. 公開前に、完成画面、維持機能、失われた詳細、実測負荷を報告する。

次の場合は公開へ進まず、事実を記録して代替画像案を検討する。

- 全国500m GeoJSONでもiPad Safariが繰り返し再読込・強制終了する。
- 等高線選択中に数秒単位で操作不能が続き、他の3表示より明確に利用困難である。
- 公開成果物へ詳細62ファイルが混入する。
- 気候、水資源、地形、農業の既存動作に回帰が出る。
- PR #21のheadが想定コミットから変わり、差分の安全な統合が確認できない。

## 11. 失われる精度と将来の再導入

軽量公開版では、拡大しても500m間隔より細かい線は表示されない。谷、盆地、山地内部の細かな傾斜変化を読む用途には向かない。地図上で選べる標高値も500m単位になる。

一方、自然環境タブの中心目的である、ロッキー山脈とアパラチア山脈、西部山地と中央平原の高さの違いは維持する。地形表示の陰影、水資源、気候区分、都市雨温図を同じ位置・倍率で切り替える比較も変わらない。

詳細版を再導入する場合は、保全済み62ファイルを再生成せず利用できる。その際は、同時取得数2件、不要リクエストの中止、展開済みデータの件数または総量上限、古い地域の削除を設計し、iPad実測を通過させてから公開する。詳細版の再導入は本設計の公開初版には含めない。

## 12. ロールバック

軽量化は、既存の全国ファイルを残したまま読込分岐と公開配置を変える小さな変更として実施する。問題が起きた場合は軽量化コミットを戻せば、PR #21の現在の縮尺別実装へ復帰できる。詳細ファイルは保全先と停止時バックアップに残るため、復帰時のデータ再取得・再生成は不要である。

本設計は承認後の実装指示に基づいて反映した。mainへの統合とGitHub Pagesへの公開状況は、`docs/atlas-nature-implementation.md`と`docs/atlas-qa.md`へ記録する。
